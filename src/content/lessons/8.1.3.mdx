## Overview <a id="overview"></a>

Easing (8.1.2) decided **when** the animation reaches each progress point. Interpolation decides **what** value sits between two control points. The two compose: easing turns time into progress, interpolation turns progress into a value, the operator from 8.1.1 turns the value into a pixel. This lesson covers the four interpolation rules you'll use 99% of the time — nearest-neighbour, linear, cosine, and Catmull-Rom — plus their 2D extension to bilinear sampling for image resize.

Linear interpolation (lerp) is the foundation: `value = a + (b - a) * t`. Everything else is a variation on that theme — cosine smooths the join, Catmull-Rom uses four neighbours to get C¹-continuous curves, bilinear blends four pixels in a 2D grid. Same idiom, more inputs. Once you can read the lerp formula by sight, every other interpolation rule is a small modification.

### Learning objectives

<ol class="obj-list">
  <li>Implement nearest-neighbour, linear, cosine, and Catmull-Rom interpolation between a sequence of control points.</li>
  <li>Recognise the difference between **smoothness through control points** (Catmull-Rom passes through them) and **smoothness between control points** (cosine smooths transitions but is still piecewise).</li>
  <li>Extend linear to **bilinear** for image resize: blend four corner pixels weighted by the fractional position.</li>
  <li>Compose interpolation with easing: `eased_value = a + (b - a) * easing(t)` — easing applied to `t`, interpolation done with the result.</li>
</ol>

## Quick start — four 1D interpolators <a id="quick-start"></a>

<CodeBlock lang="python" file="quick_start.py">
```python
import numpy as np

def lerp(t, a, b):                     # linear
    return a + (b - a) * t

def cerp(t, a, b):                     # cosine — smooth ease in/out
    eased = (1 - np.cos(t * np.pi)) / 2
    return a + (b - a) * eased

def catmull_rom(t, p0, p1, p2, p3):    # 4-point cubic spline
    return 0.5 * (
        (2 * p1)
        + (-p0 + p2) * t
        + (2 * p0 - 5 * p1 + 4 * p2 - p3) * t ** 2
        + (-p0 + 3 * p1 - 3 * p2 + p3) * t ** 3
    )
```
</CodeBlock>

<Admonition type="tip">
All four methods pass through every control point. The difference is what happens **between** the control points — the choice trades smoothness against locality (Catmull-Rom uses 4 neighbours per sample; linear uses 2; nearest uses 1).
</Admonition>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — Linear interpolation is the foundation

The lerp formula `value = a + (b - a) * t` is the most-used three operations in all of computer graphics. It works on any object you can add and scale — scalars, points, colours, matrices, anything with a vector space.

Two key properties:

- **Affine.** When `t = 0` you get exactly `a`; when `t = 1` you get exactly `b`. No drift, no rounding error.
- **Commutative end-swap.** `lerp(t, a, b) = lerp(1 - t, b, a)`. Reversing direction is free.

The pitfall is that lerp is **C⁰-continuous** but not C¹ — at every control point the velocity changes abruptly. For a sequence of waypoints, that produces visible "kinks" wherever a joint occurs. Cosine and Catmull-Rom both add smoothness; nearest-neighbour drops it entirely.

### Concept 2 — Cosine and Catmull-Rom smooth the joints

**Cosine interpolation** maps `t` through a half-cosine before lerping:

`eased = (1 - cos(t * π)) / 2`

The eased value starts at 0 with zero slope and ends at 1 with zero slope, then lerps `a` and `b` using the eased value. Per-segment smooth (C¹ at start and end), but still piecewise — adjacent segments don't share tangents at the control points.

**Catmull-Rom** uses **four** control points to compute each interior segment: the segment between `p1` and `p2` looks at `p0` and `p3` for tangent information. The resulting curve passes through every control point *and* has continuous first derivative everywhere — what graphics literature calls C¹ continuity [1].

<CodeBlock lang="python" file="catmull_rom_pseudo.py">
```python
def catmull_rom(t, p0, p1, p2, p3):
    # 4-point cubic — tangent at p1 = (p2 - p0) / 2, tangent at p2 = (p3 - p1) / 2
    return 0.5 * ((2 * p1)
                  + (-p0 + p2) * t
                  + (2 * p0 - 5 * p1 + 4 * p2 - p3) * t**2
                  + (-p0 + 3 * p1 - 3 * p2 + p3) * t**3)
```
</CodeBlock>

Catmull-Rom is the default spline for **3D camera paths**, **keyframe animation**, and **pose interpolation** in every game engine. Edwin Catmull (now retired Pixar CTO) and Raphael Rom published it in 1974 [2].

<Admonition type="dyk" title="Did you know · Catmull-Rom is just Hermite with computed tangents">
A Hermite cubic spline requires two control points and two tangent vectors per segment — four inputs total. Catmull-Rom is the same Hermite spline, but with the tangents *automatically computed* from neighbouring control points — the tangent at $p_i$ is half the difference between the next and previous control points. That is the only modification — and it removes the burden of authoring tangents by hand. Bessel and Cardinal splines are variants with different tangent rules [3].
</Admonition>

### Concept 3 — Bilinear interpolation in 2D

Linear interpolation extends to 2D by **interpolating twice**. For a continuous coordinate $(x, y)$ landing between four pixel centres, blend the four corners weighted by the fractional position:

<CodeBlock lang="python" file="bilinear_pseudo.py">
```python
def bilinear(src, y, x):
    y0, x0 = int(y), int(x)
    dy, dx = y - y0, x - x0
    # 4 corner pixels
    tl = src[y0,     x0]
    tr = src[y0,     x0 + 1]
    bl = src[y0 + 1, x0]
    br = src[y0 + 1, x0 + 1]
    # Bilinear blend
    return (
        (1 - dy) * (1 - dx) * tl
        + (1 - dy) * dx     * tr
        + dy     * (1 - dx) * bl
        + dy     * dx       * br
    )
```
</CodeBlock>

The same idea trivially extends to **trilinear** (3D textures), **bicubic** (smoother but more expensive), and **Lanczos** (a sinc-based approximation used by professional image-resize tools). For typical animation work, bilinear is the sweet spot — cheap, smooth enough, no surprises.

<Admonition type="important">
Bilinear interpolation is **separable**: you can do it as a linear interpolation along $x$ on the top row, the same along $x$ on the bottom row, then a linear interpolation along $y$ between those two results. That separability is what makes GPU texture sampling so fast — the hardware does separable linear in one instruction.
</Admonition>

**Reflection questions**

- Why does nearest-neighbour produce a staircase even when the control points are smooth?
- Catmull-Rom can **overshoot** the control-point range. With keys `[0.1, 0.7, 0.3, 0.85, 0.45]`, where in the curve does it overshoot below 0.1 or above 0.85?
- Between cosine and Catmull-Rom, which produces *smoother joints* between segments? Why?

<Dropdown summary="Answers">

**Nearest stairsteps** — nearest-neighbour assigns each input position the value of the closest single control point, ignoring all neighbours. So output transitions happen abruptly at every midpoint between control-point indices, producing piecewise-constant output.

**Catmull-Rom overshoot** — between the second and third keys (0.7 → 0.3), the slope at the second key is positive (since 0.3 < 0.7, the tangent computed from neighbours overshoots upward). The curve briefly rises *above* 0.7 before coming back down to 0.3. Visually you can spot a bump above the second control point.

**Cosine vs Catmull-Rom smoothness** — Catmull-Rom is C¹ everywhere (continuous slope across joints). Cosine is C¹ *within* each segment (slope 0 at start and end of each segment), but adjacent segments don't share their derivative at the join — slope is 0 at the right end of segment 1 and 0 at the left end of segment 2, but the *direction* changes are discontinuous in higher derivatives.

</Dropdown>

</Exercise>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

Linear interpolation `a + (b - a) * t` is the foundation of every graphics computation in this module. Cosine interpolation smooths the joins at the cost of one trig call per segment. Catmull-Rom interpolation uses 4 control points to produce C¹-continuous curves that pass through every control point — the default for camera paths and keyframe animation. Bilinear interpolation extends the same idea to 2D images by blending 4 corner pixels. Easing and interpolation compose: easing maps time to progress, interpolation maps progress to value, and the operators from 8.1.1 turn the value into pixels.

</Admonition>

**Common pitfalls to avoid**

- **Linear when smoothness matters.** Lerp between five waypoints produces visible kinks at every joint. Use Catmull-Rom or cosine for anything camera-related.
- **Bilinear without clipping.** The fractional indices can exceed the source bounds if you forget to clip `y1` and `x1` to the source size minus 1. Always clamp.
- **Catmull-Rom on small datasets.** If you have only 2 or 3 control points, Catmull-Rom degenerates badly because the auxiliary `p0` and `p3` points have to be invented. Pad with duplicates or use linear for tiny datasets.
- **Confusing easing and interpolation.** Easing reshapes time. Interpolation reshapes value. They compose; they're not interchangeable.
