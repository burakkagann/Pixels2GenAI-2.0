## Overview <a id="overview"></a>

**DMX-512** is the protocol that controls every theatre dimmer, every concert moving-head fixture, and most architectural lighting since 1986 [1]. The protocol is simple: a single XLR cable carries a stream of **512 channels**, each one a single byte (0–255), refreshed at ~44 Hz. A "universe" is one such 512-channel link. Big shows use multiple universes (8–32 is common); the largest shows use hundreds.

Every fixture has a starting **address** (channel 1 through 512) and consumes a fixed number of channels — a simple PAR can uses 3 channels (R, G, B); an RGBW fixture uses 4 (R, G, B, intensity); a moving-head fixture might use 16+ (pan, tilt, RGB, gobo, zoom, focus, etc.). Send the right bytes to the right channels and the rig lights up. This lesson uses synthesised fixtures so you can build the cue logic without a real DMX interface.

## Core concepts <a id="core-concepts"></a>

### Concept 1 — The 512-channel universe

A DMX universe is a 512-element byte array. Index 1 (DMX channels are 1-indexed) is channel 1; index 512 is channel 512. Each byte is 0–255. The whole array is transmitted every ~22 ms.

Map fixtures to channels by their **starting address**:

<CodeBlock lang="python" file="packing.py">
```python
def pack_to_dmx(fixture_states, fixture_addresses):
    universe = bytearray(512)
    for (r, g, b, intensity), addr in zip(fixture_states, fixture_addresses):
        universe[addr - 1] = r           # DMX channels are 1-indexed
        universe[addr] = g
        universe[addr + 1] = b
        universe[addr + 2] = intensity
    return bytes(universe)
```
</CodeBlock>

Real production rigs are addressed by physically setting DIP switches or a digital menu on each fixture. The Python code only needs to know which address each fixture starts at.

### Concept 2 — Fixture channel layouts

Every fixture model has a **channel layout** — what each consecutive channel means. Common layouts:

- **3-ch RGB PAR**: R, G, B.
- **4-ch RGBW**: R, G, B, intensity (or sometimes W = white channel).
- **6-ch RGBWAU**: R, G, B, W, amber, UV.
- **16-ch moving head**: pan, tilt, pan-fine, tilt-fine, R, G, B, dimmer, strobe, gobo, gobo-rotate, prism, zoom, focus, function, speed.

Always check the **fixture profile** (a small file from the manufacturer, or a community-maintained one in QLC+ or Vectorworks) before addressing. Mis-addressing makes "tilt" the same channel as "blue" — your fixture moves when you ask it to change colour.

<Admonition type="dyk" title="Did you know · DMX descends from 1980s theatre tech">
DMX-512 was standardised by USITT (United States Institute for Theatre Technology) in 1986, succeeding analog 0-10 V dimmer control [2]. The 512-channel limit was set by RS-485 serial bus timing constraints. Modern stage shows routinely use 32+ universes (16,384 channels) via Art-Net over Ethernet, but the per-universe protocol is unchanged. The Wireless DMX standards (LumenRadio CRMX, Wireless Solution W-DMX) wrap the same byte stream in a low-latency RF transport [3].
</Admonition>

### Concept 3 — Cues and transitions

A **cue** is a named lighting state: "fixtures 1–4 blue at 80%, fixtures 5–8 amber at 50%." A show is a sequence of cues with **transitions** — fade times — between them. The cue stack is essentially a state machine.

**Reflection questions**

- The rig uses 8 RGBW fixtures × 4 channels each = 32 channels. How many such rigs fit in one DMX universe?
- The strobe cue alternates between full and 30 intensity every 2 frames. At 24 fps, what's the strobe rate in Hz?
- Why is "warm alternation" a less stressful cue than "strobe" for a long-running ambient piece?

<Dropdown summary="Answers">

**Rigs per universe** — 512 / 32 = 16 rigs of 8 fixtures each. In practice you usually have more diverse fixture types (some 3-ch, some 16-ch), so a universe might host 10–30 fixtures total. Larger shows partition fixtures across many universes.

**Strobe rate** — full/dim every 2 frames at 24 fps → 12 cycles per second → 12 Hz. Real strobes go up to 25 Hz for "fast strobe" effects; epilepsy-safe shows cap at 4 Hz [4].

**Strobe vs. alternation** — warm alternation is slow (full cue cycle over 22 frames ≈ 1 second), low-amplitude (colour variation, not intensity). Strobe has 100% intensity modulation at 12 Hz — designed to grab attention. Comfortable for moments; stressful for hours.

</Dropdown>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

DMX-512 is a 512-byte universe refreshed at 44 Hz. Each fixture occupies a contiguous slice of channels starting at its address. A cue is a named lighting state; a show is a sequence of cues with timed transitions. The same `pack_to_dmx` function drives an Enttec USB interface, an Art-Net Ethernet bridge, or this synthesized renderer — only the destination differs. Mapping fixture state to channel state is straightforward Python; the protocol-level timing is handled by whichever driver you ship to.

</Admonition>

**Common pitfalls to avoid**

- **Off-by-one addressing.** DMX channels are 1-indexed; Python arrays are 0-indexed. Always `universe[addr - 1] = ...`.
- **Wrong channel layout.** Mis-addressing a moving head turns colour changes into pan-tilt sweeps. Always check the fixture profile.
- **Sending too fast or too slow.** Most fixtures handle 30 fps; some need exactly 44 Hz. Match what your destination expects.
- **No blackout cue.** Every show needs a "all off" cue for emergency stop or end-of-show. Don't forget it.
