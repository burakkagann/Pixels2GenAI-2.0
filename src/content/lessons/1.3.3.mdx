## Overview <a id="overview"></a>

Father Sébastien Truchet was an eighteenth-century Dominican friar who studied the patterns produced by square tiles split along a diagonal [1]. Take a square divided diagonally into a light triangle and a dark triangle; place many copies on a grid; rotate each one randomly to one of four orientations. The resulting wall of tiles is never the same twice, yet always cohesive — flowing curves emerge where rotations align, sharp corners appear where they clash.

This lesson re-creates Truchet's experiment in NumPy, using a single small tile rendered four ways. It is a worked example of how **rotational symmetry** plus **randomness** equals visual complexity.

### Learning objectives

<ol class="obj-list">
  <li>Construct a base tile as a small NumPy array and rotate it into four orientations.</li>
  <li>Use a 2D random index grid to choose which rotation to place at each location.</li>
  <li>Assemble a large composite image by writing tiles into a canvas with array slicing.</li>
</ol>

## Quick start — a random Truchet wall <a id="quick-start"></a>

Run this code to render a 12×12 grid of random Truchet tiles:

<CodeBlock lang="python" file="truchet_quick.py">
```python
import numpy as np
from PIL import Image

tile_size = 32
grid_size = 12

# Base tile: a diagonal split (light triangle, dark triangle)
base = np.zeros((tile_size, tile_size), dtype=np.uint8)
for y in range(tile_size):
    for x in range(tile_size):
        base[y, x] = 255 if x > y else 0

# Pre-compute all four rotations
tiles = [np.rot90(base, k) for k in range(4)]

# Choose a random orientation for each cell
np.random.seed(7)
choices = np.random.randint(0, 4, size=(grid_size, grid_size))

# Assemble the canvas
canvas = np.zeros((grid_size * tile_size, grid_size * tile_size), dtype=np.uint8)
for row in range(grid_size):
    for col in range(grid_size):
        y0 = row * tile_size
        x0 = col * tile_size
        canvas[y0:y0 + tile_size, x0:x0 + tile_size] = tiles[choices[row, col]]

Image.fromarray(canvas).save('truchet_wall.png')
```
</CodeBlock>

<Admonition type="tip">
The seed `7` controls which random orientations are chosen. Change it, and the same pair of triangles produces a completely new pattern — no two seeds give identical results because there are 4¹⁴⁴ possible arrangements of a 12×12 grid.
</Admonition>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — One tile, four orientations

The original Truchet tile is a square divided by a diagonal into two coloured triangles. With four 90° rotations, a single tile yields four distinct cells. `np.rot90` returns a rotated view of an array without copying memory; passing `k` rotates by `k * 90` degrees counter-clockwise [2].

<CodeBlock lang="python">
```python
import numpy as np

base = np.array([[1, 1, 0],
                 [1, 0, 0],
                 [0, 0, 0]])

print(np.rot90(base, 0))  # original
print(np.rot90(base, 1))  # 90° counter-clockwise
print(np.rot90(base, 2))  # 180°
print(np.rot90(base, 3))  # 270°
```
</CodeBlock>

The Truchet tile only needs the diagonal-triangle form. Curve-based variants (where each tile contains two quarter-circles) produce smoother patterns and are sometimes called "Smith tiles" after their popularisation by Cyril Stanley Smith [3].

### Concept 2 — A random index grid

The pattern is determined entirely by a small grid of integers, one per cell, each in `{0, 1, 2, 3}` selecting which rotation to draw. With NumPy this is a single call:

<CodeBlock lang="python">
```python
np.random.seed(42)
choices = np.random.randint(0, 4, size=(12, 12))
```
</CodeBlock>

The result is a `(12, 12)` array of orientations. Because it is small and serialisable, you can save it, hand-edit it, or generate it with non-random rules. For example, choosing `(row + col) % 4` gives a diagonal-striped Truchet pattern with no randomness at all.

<Admonition type="note">
Truchet originally generated his patterns by tossing a coin to pick orientations [1]. The random-index grid is the modern equivalent — a small data structure that encodes a much larger image.
</Admonition>

### Concept 3 — Composite tiling via slicing

Once you have the rotated tiles and the index grid, assembly is mechanical: loop over the grid, compute the destination slice, copy the chosen tile into it.

<CodeBlock lang="python">
```python
for row in range(grid_size):
    for col in range(grid_size):
        y0, x0 = row * tile_size, col * tile_size
        canvas[y0:y0 + tile_size, x0:x0 + tile_size] = tiles[choices[row, col]]
```
</CodeBlock>

This pattern — index grid plus a stamp loop — generalises beyond Truchet. Any procedural composition where each cell picks from a small library of motifs (Wang tiles in the next lesson, pixel-art autotiling, dungeon generation) uses the same skeleton.

## Exercises <a id="exercises"></a>

<Exercise n={1} kicker="EXECUTE" title="Run the wall and inspect">

Run the quick-start code with three different seeds (`np.random.seed(7)`, `42`, and `100`) and compare the results.

**Reflection questions**

- Do you see continuous curves or straight runs forming between cells? Why?
- What does the pattern look like at the edges of the grid?
- If you replaced `np.random.randint(0, 4, ...)` with `np.zeros((12, 12), dtype=int)`, what would you expect to see?

<Dropdown summary="Solution & explanation">

- Diagonal lines connect when neighbouring tiles have orientations that line up — for example, a 0-rotation next to a 1-rotation shares a diagonal endpoint. These chance alignments are what produce the characteristic "flowing" look. The eye groups aligned segments into longer curves.
- Edges show half-formed motifs because the canvas crops them cleanly. Toroidal wrapping (using modulo arithmetic in the index grid) makes the edges connect seamlessly.
- With all zeros, every cell uses the same orientation. The result is a globally striped pattern — no randomness, no flowing curves, just parallel diagonals across the whole canvas.

</Dropdown>

</Exercise>

<Exercise n={2} kicker="MODIFY" title="Try different base tiles">

Replace the diagonal-split base tile with three alternatives. Keep everything else the same.

<Dropdown summary="Goals">

1. **Inverted Truchet**: swap the white and black triangles in the base tile.
2. **L-shape tile**: only fill the top-left quadrant of the tile.
3. **Two-tone Truchet**: instead of black/white, use two colours (e.g. teal and warm yellow). This requires a 3D base tile of shape `(tile_size, tile_size, 3)`.

</Dropdown>

<Dropdown summary="Hint — colour Truchet">

For the two-tone version, change the base tile and canvas to RGB. Allocate a `(tile_size, tile_size, 3)` array and use `np.rot90` with `axes=(0, 1)` to preserve the channel dimension:

<CodeBlock lang="python">
```python
teal = np.array([60, 160, 175], dtype=np.uint8)
yellow = np.array([235, 200, 80], dtype=np.uint8)

base = np.zeros((tile_size, tile_size, 3), dtype=np.uint8)
for y in range(tile_size):
    for x in range(tile_size):
        base[y, x] = teal if x > y else yellow

tiles = [np.rot90(base, k, axes=(0, 1)) for k in range(4)]
canvas = np.zeros((grid_size * tile_size, grid_size * tile_size, 3), dtype=np.uint8)
```
</CodeBlock>

</Dropdown>

<Dropdown summary="Solutions">

**1. Inverted Truchet** — flip the triangle test:

<CodeBlock lang="python">
```python
base[y, x] = 255 if x < y else 0
```
</CodeBlock>

**2. L-shape tile** — fill only one quadrant:

<CodeBlock lang="python">
```python
base = np.zeros((tile_size, tile_size), dtype=np.uint8)
base[:tile_size // 2, :tile_size // 2] = 255
```
</CodeBlock>

**3. Two-tone**: see hint above.

</Dropdown>

<Exercise n={3} kicker="CREATE" title="Curved Truchet (Smith tiles)">

The smooth, flowing version of Truchet tiles draws two quarter-circles inside each square instead of a diagonal. Build the curved base tile and render a Smith-style wall.

**Goal**: Create a base tile where two quarter-circles of radius `tile_size // 2` sit in the top-left and bottom-right corners. Render a 12x12 grid of randomly-oriented copies.

<CodeBlock lang="python" file="exercise3_starter.py">
```python

from PIL import Image

tile_size = 64
grid_size = 12

# TODO 1: Create a base tile of zeros
# TODO 2: For each (y, x), set the pixel white if it is inside
#         either quarter-circle (top-left or bottom-right corner).
#         Hint: distance from corner (cy, cx) is hypot(y - cy, x - cx)
# TODO 3: Rotate into four orientations with np.rot90
# TODO 4: Choose random orientations and assemble the canvas
# TODO 5: Save as 'smith_tiles.png'
```
</CodeBlock>

<Dropdown summary="Hint — drawing the quarter-circles">

The top-left quarter-circle is centred at `(0, 0)`. A pixel `(y, x)` is inside it if `hypot(y, x) <= radius`. The bottom-right quarter-circle is centred at `(tile_size, tile_size)`:

<CodeBlock lang="python">
```python
radius = tile_size // 2
for y in range(tile_size):
    for x in range(tile_size):
        in_topleft = np.hypot(y, x) <= radius
        in_botright = np.hypot(tile_size - y, tile_size - x) <= radius
        if in_topleft or in_botright:
            base[y, x] = 255
```
</CodeBlock>

</Dropdown>

<Dropdown summary="Complete solution">

<CodeBlock lang="python" file="exercise3_solution.py">
```python
import numpy as np
from PIL import Image

tile_size = 64
grid_size = 12
radius = tile_size // 2

# Build the curved base tile
base = np.zeros((tile_size, tile_size), dtype=np.uint8)
for y in range(tile_size):
    for x in range(tile_size):
        in_topleft = np.hypot(y, x) <= radius
        in_botright = np.hypot(tile_size - y, tile_size - x) <= radius
        if in_topleft or in_botright:
            base[y, x] = 255

# Four orientations (only 0 and 1 are visually distinct, but stored uniformly)
tiles = [np.rot90(base, k) for k in range(4)]

# Random orientation grid
np.random.seed(42)
choices = np.random.randint(0, 4, size=(grid_size, grid_size))

# Assemble
canvas = np.zeros((grid_size * tile_size, grid_size * tile_size), dtype=np.uint8)
for row in range(grid_size):
    for col in range(grid_size):
        y0, x0 = row * tile_size, col * tile_size
        canvas[y0:y0 + tile_size, x0:x0 + tile_size] = tiles[choices[row, col]]

Image.fromarray(canvas).save('smith_tiles.png')
```
</CodeBlock>

**How it reads**

With curved tiles, the visual cohesion is striking — wherever two adjacent tiles share an edge, the quarter-circles either join smoothly into a half-circle or terminate at the boundary. Long, sinuous paths weave across the grid, producing the labyrinthine look that made Smith tiles popular in computer-graphics textbooks of the 1980s [3].

</Dropdown>

</Exercise>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

Truchet tiles demonstrate that visual complexity can emerge from a single motif placed at random rotations. The technique factors into three independent pieces: a base tile, four pre-computed rotations, and a small index grid that selects which rotation to draw at each cell. Each piece is replaceable — change the base, the symmetry group, or the index generator, and you get a different family of patterns. This separation of pattern and data is the foundation of every procedural-tile system that follows in this curriculum, including Wang tiles in the next lesson.

</Admonition>

**Common pitfalls to avoid**

- Forgetting `dtype=np.uint8` on the base tile causes `np.rot90` to return floats, which then quietly upcast the canvas.
- Using `axes=(0, 1)` is required when rotating RGB tiles, otherwise the channel dimension gets permuted.
- Setting `tile_size` too small (under 8 pixels) makes the triangles invisible — quantisation dominates.
