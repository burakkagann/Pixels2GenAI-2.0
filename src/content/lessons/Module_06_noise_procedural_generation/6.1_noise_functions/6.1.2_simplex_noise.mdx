## Overview <a id="overview"></a>

In 2001, almost two decades after publishing Perlin noise, Ken Perlin proposed a successor: **simplex noise**. Same goal — coherent random fields for procedural textures — but a different grid. Where Perlin noise samples a square lattice and interpolates 2ⁿ corners per sample (4 in 2D, 8 in 3D), simplex noise samples a *triangular* lattice (a "simplex") and interpolates only n+1 corners (3 in 2D, 4 in 3D) [1]. The change cuts the per-sample cost dramatically in higher dimensions and eliminates the axis-aligned bias the square grid imposes on Perlin's output. This lesson uses a Perlin-equivalent fbm pipeline to compare the two grids and explain what simplex changes for production rendering.

### Learning objectives

<ol class="obj-list">
  <li>State why simplex noise scales better than Perlin noise as dimension increases — `n+1` versus `2ⁿ` interpolation corners.</li>
  <li>Recognise the *directional bias* of Perlin noise: features tend to line up with the x and y axes, especially at low octaves.</li>
  <li>Render the simplex output and compare against Perlin / value noise — the difference is subtle in 2D but visible in motion.</li>
  <li>Choose between Perlin and simplex for new code: simplex for ≥ 3D, either for 2D.</li>
</ol>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — Square grids vs simplex grids

Perlin noise samples a **regular square lattice**: cells at integer coordinates, four corners per cell in 2D, eight in 3D, sixteen in 4D. To compute one noise value the algorithm reads `2ⁿ` corner gradients and blends them with `2ⁿ − 1` interpolation operations.

A **simplex** is the simplest possible volume in `n` dimensions:

| Dimension | Simplex shape | Corners |
|-----------|---------------|---------|
| 1         | Line segment  | 2       |
| 2         | Triangle      | 3       |
| 3         | Tetrahedron   | 4       |
| 4         | Pentatope     | 5       |
| n         | n-simplex     | n+1     |

Simplex noise tiles the space with `n`-simplices (equilateral triangles in 2D, regular tetrahedra in 3D) and only needs `n+1` corner contributions per sample. In 4D the saving is dramatic: 5 corners vs 16 [1].

### Concept 2 — No axis-aligned bias

Perlin noise on a square grid has a subtle visual artefact: features tend to line up with the x and y axes. The effect is faint in 2D but accumulates in higher dimensions, especially for animated noise where the time axis becomes a *third dimension*. Simplex's triangular tiling breaks the axis alignment — its features have no preferred direction.

A different way to see the same thing: a square cell has rotational symmetry only at 90°. An equilateral triangle has 120° symmetry; tile them and you get the *honeycomb* arrangement (60° symmetry overall). Six-fold symmetry hides the grid more effectively than four-fold [2].

<Admonition type="dyk" title="Technical note · the 2001 patent">
Ken Perlin patented simplex noise in 2001 (US Patent 6,867,776 B2). The patent expired in 2022, freeing the algorithm for any use. Until then, several Open-source projects — including the popular *OpenSimplex* — were created specifically to deliver the same look without infringing. The math hasn't changed; only the licensing did [3].
</Admonition>

### Concept 3 — Production trade-offs

For typical 2D texture work, value noise and Perlin noise are visually indistinguishable from simplex. The reason to reach for simplex is:

- **High dimensions** — 3D textures, 4D animated 3D noise, any time you would otherwise pay `2ⁿ` corner reads.
- **No directional artefacts** — required for procedural normal maps, shader noise on rotating surfaces, etc.
- **Edge cases in derivatives** — simplex noise has cleaner analytical derivatives, useful for procedural normal mapping.

Trade-offs in the other direction:

- Simplex implementations are *longer* and harder to read than Perlin.
- Some shader languages still ship Perlin noise as a built-in primitive; simplex must be hand-rolled.

The rule of thumb in 2024: **use simplex for ≥ 3D and for animated noise; either is fine for static 2D textures** [4].

## Exercises <a id="exercises"></a>

Three short exercises in **Execute → Modify → Create** order: render the field, sweep parameters, then animate.

<Exercise n={1} kicker="EXECUTE" title="Render the simplex-style field">

Run `simplex_field.py`. It re-uses the value/Perlin fbm pipeline from 6.1.1 — the result is what simplex looks like at 2D.

**Reflection questions**

- How does this image differ visually from the 6.1.1 quick-start image?
- What would change about the *cost* of generating this image in true simplex code, in 2D? In 3D?
- Why would simplex matter most when noise is animated over time?

<Dropdown summary="Answers">

**Visual difference** — slim. At the level of a single static 2D image with a few octaves, value/Perlin/simplex look similar. The differences emerge under derivatives (lighting), under rotation (textures sliding past each other), and at very low octave counts (where Perlin's axis bias becomes visible).

**Cost** — in 2D, simplex saves one corner read per sample (3 vs 4). In 3D it saves 4 corner reads per sample (4 vs 8). In 4D, 11 corner reads per sample (5 vs 16). Higher-dimensional procedural texturing is where simplex shines.

**Animation** — adding a time axis effectively makes 2D noise into 3D. Perlin's axis bias then includes "alignment with the time direction," which manifests as features that pulse straight up and down rather than meander. Simplex's symmetric tile breaks that.

</Dropdown>

</Exercise>

<Exercise n={2} kicker="MODIFY" title="Three parameter sweeps">

Edit the script to try three configurations.

**Goals**

1. **Single octave** — `octaves=1`. With Perlin noise on a square grid you would see a subtle axis-aligned look; value noise is similar but with a different cell pattern.
2. **High persistence** — `persistence=0.8`. The detail piles up; the picture is rougher.
3. **Different seed** — `seed=99`. Same statistics, different specific pattern.

<Dropdown summary="Goal 1 — what to expect">

Smooth blobby shapes at a single scale. The cell-grid origin is faintly visible if you look carefully — that is exactly the kind of artefact simplex's triangular grid is designed to remove.

</Dropdown>

<Dropdown summary="Goal 2 — what to expect">

Persistence 0.8 means each octave is *almost* as strong as the previous. The fine detail dominates; the overall picture looks like rough sandpaper rather than soft clouds.

</Dropdown>

<Dropdown summary="Goal 3 — what to expect">

Same parameters, different random samples. The statistics — cell size, smoothness, octave structure — are identical; only the specific pattern moves.

</Dropdown>

<Dropdown summary="Complete solution">

<CodeBlock lang="python" file="exercise3_solution.py">
```python
import numpy as np
from PIL import Image

# fbm() helpers from 6.1.1 assumed in scope

H, W, N = 200, 200, 30
zA = fbm((H, W), scale=60, octaves=4, seed=0)
zB = fbm((H, W), scale=60, octaves=4, seed=1)

for i in range(N):
    t = i / (N - 1)
    z = (1 - t) * zA + t * zB
    Image.fromarray((z * 255).astype(np.uint8), 'L').save(f'frame_{i:03d}.png')

# Optional GIF
try:
    import imageio
    frames = [np.array(Image.open(f'frame_{i:03d}.png')) for i in range(N)]
    imageio.mimsave('drift.gif', frames, fps=10)
except ImportError:
    pass
```
</CodeBlock>

**How it works:**

- Interpolating two fbm fields with `(1 - t) A + t B` produces a *continuous* morph that has the same statistical look as either field at every intermediate `t`.
- In a true simplex animation you would instead add a third dimension (time) and slide along it — the morph becomes smoother because consecutive frames sit on the same coherent volume.

</Dropdown>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

Simplex noise is Ken Perlin's 2001 replacement for his own 1985 Perlin noise. Same goal — smooth, coherent random fields — but a triangular lattice instead of a square one. The simplex grid has fewer corners per cell (`n+1` instead of `2ⁿ`), so the algorithm scales dramatically better in 3D and 4D where Perlin noise pays `2³ = 8` or `2⁴ = 16` interpolation corners per sample. The triangular tiling also eliminates the subtle axis-aligned bias of Perlin's square grid — important for procedural normal maps and any time the noise is animated over time. For static 2D textures the visible difference is minimal; for ≥ 3D or animated noise, simplex is the production choice.

</Admonition>

**Common pitfalls to avoid**

- Treating "simplex" and "Perlin" as identical — they share the same coherent-noise *concept* but very different implementations.
- Reaching for simplex in 2D when value/Perlin would do — extra implementation complexity for no visible gain.
- Forgetting the patent — simplex was patented until 2022. Pre-2022 code may need licensing; post-2022, it is free.
- Comparing simplex against random noise — that is the wrong baseline. Compare against Perlin or value noise.
- Assuming simplex is *always* faster — for 1D and 2D the differences are small; the win is in 3D+.
