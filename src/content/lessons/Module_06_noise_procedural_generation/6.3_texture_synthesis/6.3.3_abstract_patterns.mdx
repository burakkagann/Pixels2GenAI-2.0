## Overview <a id="overview"></a>

**Domain warping** is one of the most visually striking procedural techniques: sample a noise field at coordinates that have themselves been displaced by *another* noise field. The result twists clean fbm into smoky, swirling, abstract patterns reminiscent of dye in water or interstellar nebulae. Inigo Quilez popularised the technique in a widely-read 2008 article whose title — *"domain warping"* — became the standard name [1]. The implementation is short (a few NumPy lines on top of fbm), but the visual result is dramatic and surprisingly versatile.

### Learning objectives

<ol class="obj-list">
  <li>Sample a noise field at displaced coordinates: `result = noise(x + warp_x(x, y), y + warp_y(x, y))`.</li>
  <li>Build the displacement fields with `qx, qy = fbm(...) − 0.5` so they range over both signs.</li>
  <li>Tune the warp amplitude — small = gentle ripple, large = chaotic swirl.</li>
  <li>Map the warped field through a two-stop colour ramp for the final abstract image.</li>
</ol>

## Quick start — single-level domain warp <a id="quick-start"></a>

<CodeBlock lang="python" file="quick_start.py">
```python
import numpy as np
from PIL import Image
# fbm() from 6.1.1 in scope

H, W = 400, 400

# Two independent noise fields used as displacement
qx = fbm((H, W), scale=90, octaves=4, seed=100) - 0.5
qy = fbm((H, W), scale=90, octaves=4, seed=101) - 0.5

# Coordinate grid + warp
y, x = np.indices((H, W)).astype(np.float64)
warp_amount = 80
yw = np.clip(y + warp_amount * qy, 0, H - 1).astype(int)
xw = np.clip(x + warp_amount * qx, 0, W - 1).astype(int)

# Sample a base noise field at the displaced coordinates
base = fbm((H, W), scale=50, octaves=4, seed=102)
warped = base[yw, xw]

Image.fromarray((warped * 255).astype(np.uint8), 'L').save('domain_warp.png')
```
</CodeBlock>

<Admonition type="tip">
The core idea is *coordinate substitution*: instead of sampling `base[y, x]`, sample `base[y + dy, x + dx]` where `dy, dx` are noise fields themselves. The same trick generalises to any function — sample colour gradients, distance fields, or even photographs at warped coordinates.
</Admonition>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — Coordinate substitution

Standard noise sampling produces a smooth field directly:

```python
base = fbm((H, W), scale=50, octaves=4)        # smooth blobs
```

Domain warping inserts an extra step *before* sampling. Replace `(x, y)` with displaced coordinates `(x + dx(x, y), y + dy(x, y))`:

```python
warped[y, x] = base[y + dy(y, x), x + dx(y, x)]
```

Each output pixel reaches into the base noise at a *shifted* location. The displacement field itself is smooth, so neighbouring pixels reach into nearby base locations — the result remains continuous, but the structure of the base noise gets twisted.

In NumPy this is one line of fancy indexing once you have the integer displaced grids:

```python
yw = (y + warp_amount * qy).astype(int)
xw = (x + warp_amount * qx).astype(int)
warped = base[yw, xw]
```

The `np.clip` after the displacement prevents out-of-bounds access at the canvas edges [2].

### Concept 2 — Displacement fields are noise too

The displacement fields `qx, qy` are themselves fbm — that is what makes the warp organic instead of geometric. Two independent noise fields (different seeds, otherwise identical parameters) give you a smooth 2D vector field:

```python
qx = fbm((H, W), scale=90, octaves=4, seed=100) - 0.5
qy = fbm((H, W), scale=90, octaves=4, seed=101) - 0.5
```

Subtracting 0.5 centres each field around zero so the displacements can be both positive and negative. Multiplying by `warp_amount` controls the scale — typical values are 30 to 100 for moderate warping.

The displacement field's *scale* matters too. If it's larger than the base noise's features, the warp moves whole blobs around; if smaller, individual blob boundaries get rippled. A 1.5× ratio between displacement and base scale gives a balanced organic look [1].

### Concept 3 — Recursive warping

The Quilez article goes further: warp the *warp* fields themselves. Two-level warping:

```python
# First warp: displace coordinates that we'll then re-displace
qx2 = fbm_at(x + 4 * qx, y + 4 * qy, ...)
qy2 = fbm_at(x + 4 * qx, y + 4 * qy, ...)

# Second warp: use the once-warped fields as new displacement
warped = base_at(x + 8 * qx2, y + 8 * qy2)
```

Two-level warping turns the output noticeably more chaotic — eddies inside eddies, fractal swirls. It's also `2×` the noise cost. The quick start uses one level for clarity; production code routinely uses two or three [1].

<Admonition type="dyk" title="Technical note · domain warping in shaders">
Quilez's article is one of the most-shared procedural-art references on the web. The technique is universal — it appears in *Shadertoy* fragments, Photoshop filters, generative art platforms, and increasingly in neural-network conditioning (where it's used to add controlled distortion to latent maps). The NumPy version here makes the math explicit; in a GPU shader it's three lines [1].
</Admonition>

<Exercise n={1} kicker="EXECUTE" title="Run the single-level warp">

Run `domain_warp.py` from the quick start.

**Reflection questions**

- The displacement field is smooth fbm, yet the output looks chaotic. Why?
- What does `warp_amount = 0` produce?
- Why do we use *two* independent displacement fields `qx` and `qy` instead of just one?

<Dropdown summary="Answers">

**Smooth displacement, chaotic output** — small smooth displacements in the *coordinate* space can produce large discontinuities in *features* of the base noise. A small shift left, then a slightly larger shift left, then back — the base noise's blobs end up sampled at completely different places, and reading the output you see the blob *boundaries* warped chaotically even though each individual displacement is small.

**Amount 0** — no displacement at all. The output is just `base[y, x]` — the unwarped fbm. Useful baseline.

**Two independent fields** — `qx` and `qy` must be independent so the 2D vector at each pixel can point in any direction. Using a single noise field for both would make `(dx, dy)` constrained to a line, and the warp would become directional instead of free.

</Dropdown>

<CodeBlock lang="python" file="exercise3_solution.py">
```python
import numpy as np
from PIL import Image
# fbm() from 6.1.1 in scope

H, W = 400, 400
y, x = np.indices((H, W)).astype(np.float64)

qx = fbm((H, W), scale=90, octaves=4, seed=100) - 0.5
qy = fbm((H, W), scale=90, octaves=4, seed=101) - 0.5

ya = np.clip(y + 60 * qy, 0, H - 1).astype(int)
xa = np.clip(x + 60 * qx, 0, W - 1).astype(int)
qx2 = fbm((H, W), scale=90, octaves=4, seed=200)[ya, xa] - 0.5
qy2 = fbm((H, W), scale=90, octaves=4, seed=201)[ya, xa] - 0.5

yb = np.clip(y + 80 * qy2, 0, H - 1).astype(int)
xb = np.clip(x + 80 * qx2, 0, W - 1).astype(int)
base = fbm((H, W), scale=50, octaves=4, seed=300)
warped = base[yb, xb]

warm = np.array([0.95, 0.30, 0.40])
cool = np.array([0.10, 0.30, 0.55])
rgb = warped[..., None] * warm + (1 - warped[..., None]) * cool

Image.fromarray((np.clip(rgb, 0, 1) * 255).astype(np.uint8)).save('domain_warp_color.png')
```

**How it works:**

- Level 1: standard displacement field from fbm.
- Level 2: sample two new fbm fields at coordinates *already displaced* by level 1. The result is a more complex displacement vector field.
- Final: sample the base noise at coordinates displaced by the level-2 fields.
- The colour ramp turns the `[0, 1]` field into a dramatic two-tone abstract.

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

Domain warping samples a noise field at coordinates that have been displaced by *other* noise fields. Two independent fbm fields `qx, qy` (centred around 0) give you a 2D displacement vector at each pixel. Add `warp_amount × (qx, qy)` to the coordinate grid and sample the base noise at the shifted positions — the smooth fbm becomes a swirling abstract. Tune `warp_amount` for severity (20 gentle, 100+ chaotic) and the displacement field's scale for swirl size (small = tight eddies, large = broad movements). Recursive warping (using one warp's output as another warp's input) compounds the complexity. The technique is universal in procedural art and shows up everywhere from Shadertoy demos to neural-network conditioning.

</Admonition>

**Common pitfalls to avoid**

- Forgetting to subtract 0.5 from the displacement fields — they end up biased one direction.
- Out-of-bounds indexing — without `np.clip` the integer displaced coordinates can land outside `[0, H)` or `[0, W)`.
- Reusing the same seed for `qx` and `qy` — they become identical fields and the displacement collapses to a 1D pattern.
- Using `np.float64` indexing for the final sample — NumPy needs integer indices. Cast to `int` *after* the clip.
- Too small a displacement field scale — the displacement becomes high-frequency noise and the output is just static.
