## Overview <a id="overview"></a>

Raw fbm terrain is *too sharp* to look natural. Real landscapes are weathered — water has carved valleys, gravity has rounded ridges, and thermal cycles have crumbled high-angle slopes. A simple **erosion** model captures the most important of these effects in a few iterations: at every step, each cell sheds a fraction of its material to its lowest downhill neighbour [1]. The result is smoother terrain with characteristic flow patterns, much closer to satellite imagery of real ground. This lesson implements the simplest viable thermal erosion in NumPy — no fluid simulation, no sediment, just gravity-driven smoothing — and lets you read the difference against the raw input.

### Learning objectives

<ol class="obj-list">
  <li>Define thermal erosion as "material moves from steep cells to downhill neighbours" and contrast it with hydraulic erosion.</li>
  <li>Compute 4-neighbour gradients with `np.pad` shifts and identify the downhill direction.</li>
  <li>Iterate an erosion step many times to converge on smoother terrain; stop when the change per iteration becomes small.</li>
  <li>Compare the raw and eroded height maps and read the differences as carved valleys and rounded peaks.</li>
</ol>

## Quick start — thermal erosion in 60 iterations <a id="quick-start"></a>

<CodeBlock lang="python" file="quick_start.py">
```python
import numpy as np
from PIL import Image
# fbm() from 6.1.1 assumed in scope

H, W = 256, 256
elev = fbm((H, W), scale=80, octaves=5, seed=7 + 50).copy()
before = elev.copy()

for _ in range(60):
    # Four-neighbour gradients
    dN = np.pad(elev[1:],     ((0, 1), (0, 0)), mode='edge') - elev
    dS = np.pad(elev[:-1],    ((1, 0), (0, 0)), mode='edge') - elev
    dE = np.pad(elev[:, 1:],  ((0, 0), (0, 1)), mode='edge') - elev
    dW = np.pad(elev[:, :-1], ((0, 0), (1, 0)), mode='edge') - elev
    # Lowest neighbour (largest negative drop)
    downhill = np.minimum(np.minimum(dN, dS), np.minimum(dE, dW))
    # Move 1/8 of the drop out of this cell each step
    flow = -0.125 * np.clip(downhill, None, 0)
    elev = elev - flow

# Normalise both for visualisation
def norm(z): return (z - z.min()) / (z.max() - z.min())
before = norm(before); after = norm(elev)

gap = np.zeros((H, 8))
side = np.hstack([before, gap, after])
Image.fromarray((side * 255).astype(np.uint8), 'L').save('erosion_before_after.png')
```
</CodeBlock>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — Thermal vs hydraulic erosion

Real-world erosion has two main flavours:

- **Thermal erosion** — gravity-driven. Material on steep slopes crumbles and falls to the lowest downhill neighbour. Cheap to simulate; produces rounded ridges and smooth valleys.
- **Hydraulic erosion** — water-driven. Rainfall accumulates into streams that carry sediment from high to low elevations, depositing it in lakes and floodplains. Realistic but much more expensive — requires a flow simulation [2].

This lesson uses thermal erosion because it captures most of the visual smoothing in a few lines of NumPy. Hydraulic erosion is one possible extension for the "Make it your own" section.

### Concept 2 — Downhill detection via padded shifts

For every cell, we want the elevation *difference* to each of its four cardinal neighbours. The padded-shift trick from 3.2.3 does this in one slice operation per direction:

```python
dN = np.pad(elev[1:], ((0, 1), (0, 0)), mode='edge') - elev
```

`elev[1:]` is the array minus its top row. Padding back on the bottom with `mode='edge'` (replicating the last row) gives a same-size array shifted one pixel *up*. Subtracting `elev` from it gives the elevation of the *southern* neighbour minus the current cell — i.e. how much higher (positive) or lower (negative) the cell to the south is.

Repeat for the three other directions. `np.minimum` over all four gives the steepest downhill direction for every cell.

### Concept 3 — Iterate, don't solve

Thermal erosion has a closed-form steady state (a perfectly flat plain), which is not what we want. The artistic value lives in the *transient* between raw noise and final equilibrium. The right approach is to iterate the step many times with a small per-iteration transport coefficient (1/8 in the quick start), and *stop* before the picture flattens:

```python
for _ in range(N_STEPS):
    apply_one_step()
```

How many steps? Try `60`. Watch the output flatten over `200` steps. Run `5000` and you get nearly featureless terrain. The right value depends on how strong the per-step transport coefficient is — small coefficient, more iterations.

<Admonition type="dyk" title="Technical note · talus angle">
Real thermal erosion has a *talus angle* — the maximum stable slope a granular material can hold (sand: 30°, gravel: 35°, snow: 38°). Production erosion code only moves material when the local slope *exceeds* the talus angle. The quick-start code skips this and moves material proportional to the drop on every step — it works visually, but real geologists would object [3].
</Admonition>

<Exercise n={1} kicker="EXECUTE" title="Run the 60-step erosion">

Run `erosion.py` from the downloads. Inspect both the before and after images.

**Reflection questions**

- Why do the peaks become rounder while the valleys widen?
- What happens if you skip the `np.clip(..., None, 0)` clamp?
- If you keep iterating to 1000 steps, what does the terrain converge to?

<Dropdown summary="Answers">

**Rounded peaks, widening valleys** — peaks are surrounded by downhill neighbours in all directions, so they shed material outward and lose elevation faster. Valleys *receive* the material, but they receive it from many sources, so they fill in.

**Without the clamp** — `np.minimum` would return a *positive* value where all four neighbours are higher (i.e. the cell is in a pit). Without the clamp, we would *remove* material from pits, which is the opposite of physical behaviour — pits should *receive* sediment.

**1000 iterations** — the terrain approaches a flat plain. Each step lowers high cells and raises low cells; the steady state is everything at the mean elevation. The artistic sweet spot is far before this.

</Dropdown>

</Exercise>

<Dropdown summary="Complete solution">

<CodeBlock lang="python" file="exercise3_solution.py">
```python
import numpy as np
from PIL import Image
# fbm() from 6.1.1 assumed in scope

H, W = 400, 400
raw = fbm((H, W), scale=120, octaves=6, seed=42)
elev = raw.copy()

for _ in range(60):
    dN = np.pad(elev[1:],     ((0, 1), (0, 0)), mode='edge') - elev
    dS = np.pad(elev[:-1],    ((1, 0), (0, 0)), mode='edge') - elev
    dE = np.pad(elev[:, 1:],  ((0, 0), (0, 1)), mode='edge') - elev
    dW = np.pad(elev[:, :-1], ((0, 0), (1, 0)), mode='edge') - elev
    downhill = np.minimum(np.minimum(dN, dS), np.minimum(dE, dW))
    flow = -0.125 * np.clip(downhill, None, 0)
    elev = elev - flow

def norm(z): return (z - z.min()) / (z.max() - z.min())

def biome_color(elev_norm):
    levels = [
        (0.30, (0.05, 0.20, 0.55)),
        (0.45, (0.10, 0.45, 0.80)),
        (0.55, (0.85, 0.78, 0.45)),
        (0.75, (0.20, 0.50, 0.20)),
        (0.90, (0.45, 0.35, 0.25)),
        (1.01, (0.95, 0.95, 0.98)),
    ]
    rgb = np.zeros((*elev_norm.shape, 3))
    last = 0.0
    for cap, color in levels:
        m = (elev_norm <= cap) & (elev_norm > last)
        rgb[m] = color
        last = cap
    return rgb

before_rgb = biome_color(norm(raw))
after_rgb = biome_color(norm(elev))
gap = np.zeros((H, 8, 3))
side = np.hstack([before_rgb, gap, after_rgb])
Image.fromarray((side * 255).astype(np.uint8)).save('eroded_biomes.png')
```
</CodeBlock>

**How it works:**

- The erosion loop reshapes the elevation; the biome map is just the same colour function applied to either field.
- The eroded version has wider valleys (more low-elevation pixels read as water/beach) and softer ridges (less snow on top).
- Normalising before applying biome colours keeps both images in `[0, 1]` so the thresholds are comparable.

</Dropdown>

#### Make it your own

- Add a *deposit* step: track the material removed from each cell and add it to the downhill neighbour. The total elevation is conserved (mass-conservation); the picture flattens slower.
- Skip the talus-angle check at first; add it later with `if downhill < -TALUS: flow = ...`.
- Combine with the cellular-automata cave generator (6.2.3) to carve out subterranean caves under your terrain.

</Exercise>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

Thermal erosion is gravity-driven smoothing of a height map: each iteration moves material from every cell to its lowest downhill neighbour. Implemented in NumPy as four `np.pad` shifts to compute neighbour gradients, plus `np.minimum` for the steepest downhill direction, plus a transport coefficient (typically 0.125) times the number of iterations (typically 60). The terrain steadily smooths over iterations — peaks round off, valleys widen, ridges soften. The artistic value lives in the transient, not the steady state (which is a flat plain). Hydraulic erosion adds realistic stream patterns at substantially higher cost; thermal erosion captures most of the perceptual benefit in a one-screen implementation.

</Admonition>

**Common pitfalls to avoid**

- Skipping the `np.clip(downhill, None, 0)` clamp — material is removed from pits that should be filling.
- Using too large a transport coefficient — values above 0.5 can produce numerical ringing or unstable patterns.
- Iterating to convergence — the steady state is a flat plain. Stop while there is still structure.
- Comparing raw and eroded *without* normalising both — the erosion shrinks the overall dynamic range, so a direct PNG of the eroded array looks darker than it should.
- Treating thermal erosion as a *substitute* for hydraulic — thermal smooths, hydraulic *carves*. They produce different aesthetics; use both for realistic terrain.
