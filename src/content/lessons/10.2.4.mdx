## Big Question — *why is real-time fractal rendering only possible on the GPU?* <a id="big-question"></a>

The Mandelbrot set requires evaluating the iteration `z ← z² + c` until either `|z| > 2` or you hit an iteration cap, *per pixel*. At 1080p that is roughly 2 million pixels. Even with NumPy vectorisation, the CPU version from lesson 4.1.3 takes 100-500 ms per frame at modest iteration counts — fine for offline rendering, useless for interactive zoom. GPUs, by contrast, *exist* to do this kind of embarrassingly-parallel per-pixel work. A modern GPU executes a fragment shader independently for every pixel, in parallel across thousands of cores. A 1080p Mandelbrot at 200 iterations renders in under 2 ms on a mid-range GPU. That speed unlocks the genuinely interesting interaction: **deep zoom in real time**. You can scroll your mouse and the set re-renders at 60 fps, with the zoom level rising into the millions before single-precision floats lose their precision and the image gets blocky. **GLSL TOP** is TouchDesigner's interface to write fragment shaders, and porting the Mandelbrot is the cleanest first GLSL exercise.

## Part 1 — The per-pixel-independence property <a id="part-1"></a>

A pixel's colour in the Mandelbrot set depends only on its coordinates. No pixel's calculation needs another pixel's result. This is called **embarrassingly parallel**, and it is the property that GPUs were originally designed to exploit. A GLSL fragment shader runs your function once per pixel, in parallel across the entire image, with effectively zero communication overhead. There is *no faster way* to render Mandelbrot than via fragment shader; the architecture is purpose-built for this workload [1].

By contrast, simulations with global dependencies — sequential Markov chains, recurrent neural nets, anything where step `t+1` needs step `t` — do not parallelise across pixels and gain little from GPU rendering. The Mandelbrot's complete independence is why this lesson exists in Module 10.2 (mappings) rather than Module 10.3 (heavy compute).

## Part 2 — A minimal fragment shader <a id="part-2"></a>

A fragment shader is a function that takes a pixel's UV coordinates and outputs its colour. The skeleton:

<CodeBlock lang="glsl" file="shader_skeleton.glsl">
```glsl
out vec4 fragColor;
void main() {
    vec2 uv = vUV.xy;            // current pixel's normalized coords [0,1]
    vec3 col = vec3(uv.x, uv.y, 0.5);
    fragColor = vec4(col, 1.0);
}
```
</CodeBlock>

Drop this into a `GLSL TOP`'s fragment-shader pane and the output is a gradient that runs red horizontally and green vertically. `vUV.xy` is supplied by TD (the pixel's UV coordinates `[0, 1]`). `fragColor` is the output colour with alpha.

The Mandelbrot version remaps `uv` to a region of the complex plane, iterates `z ← z² + c` until escape, and colours by the iteration count:

<CodeBlock lang="glsl" file="mandelbrot.glsl">
```glsl
uniform vec2 uCentre;
uniform float uZoom;
uniform int uMaxIter;
out vec4 fragColor;

void main() {
    vec2 uv = vUV.xy * 2.0 - 1.0;       // [-1, 1]
    vec2 c = uCentre + uv * uZoom;
    vec2 z = vec2(0.0);
    int i;
    for (i = 0; i < uMaxIter; i++) {
        z = vec2(z.x * z.x - z.y * z.y,
                 2.0 * z.x * z.y) + c;
        if (dot(z, z) > 4.0) break;
    }
    float t = float(i) / float(uMaxIter);
    vec3 col = vec3(t, t * t, sqrt(t));
    fragColor = vec4(col, 1.0);
}
```
</CodeBlock>

That is the entire algorithm, in 16 lines of GLSL. `uCentre`, `uZoom`, and `uMaxIter` are *uniforms* — parameters passed in from TouchDesigner.

<Admonition type="dyk" title="Did you know? · Demoscene history">
The demoscene — a community of programmers who pack visual demos into tiny executables, often 4 KB or smaller — has been writing GLSL fractal shaders since the early 2000s. Inigo Quílez's *Shadertoy* (2013) made the format mainstream and is now the canonical place to learn GLSL. Many of the shader tricks used in commercial 3D engines first appeared on Shadertoy as demoscene experiments [3].
</Admonition>

## Part 3 — Connecting TD parameters to shader uniforms <a id="part-3"></a>

The GLSL TOP has a `Vectors` and `Constants` parameter page where you declare uniforms and bind them to TD values (constants, parameter expressions, or CHOP outputs). The flow:

1. Write the shader with `uniform vec2 uCentre; uniform float uZoom;` etc.
2. In the GLSL TOP parameters, add a vector named `uCentre` (xy) and a constant named `uZoom` and `uMaxIter`.
3. Bind their values: drag a CHOP onto the parameter, type an expression like `me.par.tx`, or just enter constants.

To make zoom interactive, wire a mouse-position CHOP into `uCentre` and use a slider parameter for `uZoom`. The Mandelbrot re-renders at every mouse movement, at 60 fps.

For deeper zoom (>10⁶ magnification), you need **double-precision** GLSL. Standard `float` runs out of precision near zoom 10⁵; `double` (GL extension `GL_ARB_gpu_shader_fp64`) gets you to about 10¹⁴. Beyond that requires arbitrary-precision math, which kills GPU speed.

<Admonition type="important">
The single biggest mistake when writing GLSL shaders: writing CPU code patterns into GLSL. There are no objects, no dynamic allocation, no recursion in pre-shader-model-5 GLSL. Loops must have static bounds when possible. Use `vec2`, `vec3`, `vec4` instead of arrays. Read at least one shader tutorial before your first long shader.
</Admonition>

## Synthesis project — interactive Mandelbrot explorer <a id="synthesis"></a>

Build a GLSL TOP that renders the Mandelbrot set. Wire mouse position into `uCentre`, mouse-wheel into `uZoom` (via a Speed CHOP integrator). Expose `uMaxIter` as a slider. The result is a real-time explorer that goes as deep as single-precision allows.

**Reflection questions**

- Why does the same Mandelbrot fragment shader work for the Julia set with one tiny change?
- Compare the GPU version to your Python implementation from lesson 4.1.3 — what is the speedup, and what causes most of it?
- Above what zoom level does the image become visibly blocky, and what is the cause?

<Dropdown summary="Answers">

**Mandelbrot to Julia in one change** — for Julia, `c` is constant across the image and `z` is initialised from the pixel coordinate. Swap the two: `vec2 z = uv; vec2 c = uConstC;` and the Julia set falls out. Same iteration body, different initial conditions. Module 4.1.4 explains this in depth.

**Speedup** — typically 100–500× over NumPy. Two causes: (1) the GPU has thousands of cores running in parallel, where NumPy uses ~10–100 SIMD lanes. (2) The GLSL escape-test branches inside the shader; NumPy must compute all iterations and mask afterward, wasting work on early-escape pixels.

**Single-precision limit** — around zoom 10⁵ on most GPUs. Single-precision `float` has 23 bits of mantissa, about 7 decimal digits. When you zoom 10⁵×, your fractional coordinates need at least 5-6 extra digits of precision. Beyond that, neighbouring pixels round to the same value and you see chunky bands.

</Dropdown>

#### Make it your own

- **Smooth colouring**: use the continuous iteration count `i - log2(log2(|z|²))` instead of the integer count. The colour bands disappear.
- **Julia mode**: add a `uMode` uniform and switch between Mandelbrot and Julia in one shader.
- **Animate `c`**: when in Julia mode, animate `uConstC.xy` along a path. The Julia set morphs continuously.
- **Higher iteration**: dynamically increase `uMaxIter` as you zoom in. Deeper zooms need more iterations to resolve fine detail.

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

Fractals are the canonical first GLSL exercise because they are embarrassingly parallel and have no global state. A GLSL TOP runs your fragment shader per pixel in parallel on the GPU at 60+ fps for 1080p output. The Mandelbrot iteration fits in 16 lines of GLSL; the Julia set is one tweak away. Uniforms bind TD parameters or CHOP outputs into shader inputs, enabling real-time interaction. Single-precision GLSL bottoms out at zoom ~10⁵; double-precision GLSL extends to ~10¹⁴ but is not supported on all GPUs. Beyond fractals, the same shader architecture renders raymarched 3D scenes, signed-distance-field art, post-processing effects, and most of modern real-time graphics.

</Admonition>

**Common pitfalls to avoid**

- Writing GLSL like Python — using lists, dictionaries, recursion. GLSL is C-with-vectors; structure your code accordingly.
- Forgetting to declare uniforms in TD. The shader compiles but uniform values stay zero.
- Using `float` zoom past 10⁵. Switch to `double` or accept blocky output.
- Returning `vec3` from `main()`. The output must be `vec4` (with alpha) for TD's `fragColor` interface.
- Animating `uMaxIter` discontinuously. Bumping the iteration count from 50 to 500 mid-render produces a visible "fill in" effect.
