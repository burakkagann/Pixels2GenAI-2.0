## Big Question — *what is the smallest abstraction that lets a live performer change everything at once?* <a id="big-question"></a>

A live VJ might have 30 visual parameters spread across 8 components — colour palette, blur, noise frequency, particle count, audio reactivity weights, postprocess strength. Adjusting them one by one between songs is impossible. The solution every show-control system from the 1970s onwards has converged on is the **preset**: a named snapshot of every relevant parameter at one moment, recalled by pressing a single button or sending a single MIDI message. Sophisticated versions add **interpolation** — fade smoothly from preset A to preset B over 4 seconds, and every parameter slides through the in-between. TouchDesigner does not have a built-in preset system; you build your own. The architecture is small and once built, ships across every project. It is also the natural test of everything you have learned in this module — components, custom parameters, scripts, CHOPs, UI.

### Learning objectives

<ol class="obj-list">
  <li>Design a preset as a key-value snapshot: parameter path → current value.</li>
  <li>Implement save and recall via a Script DAT that walks a fixed parameter list.</li>
  <li>Interpolate between two presets by writing a per-frame Lerp using `me.par.X = (1-t)*a + t*b`.</li>
  <li>Store presets in a Table DAT (in-memory) or on disk (JSON file via `me.storage`).</li>
</ol>

## Part 1 — Preset as a key-value snapshot <a id="part-1"></a>

A preset is a dictionary mapping parameter paths to values:

```
preset_A = {
  '/visuals/noise1.par.period': 100,
  '/visuals/blur1.par.size': 12,
  '/visuals/level1.par.bright': 0.8,
  '/visuals/level1.par.contrast': 1.2,
  ...
}
```

The "parameter path" is whatever uniquely identifies a parameter. The "value" is its current numeric/string state. Saving a preset means walking every parameter in the list and copying its current value; recalling means walking the list in reverse and writing each value back.

The key design decision is *the list of parameters to manage*. Two strategies:

- **Whitelist**: maintain an explicit list of parameters that participate. Predictable; you know exactly what changes.
- **Walk the network**: programmatically discover every parameter on every operator. Powerful, but accidentally saves built-in parameters (Cook Type, Display) that should not be in presets.

For a polished system, use the whitelist. Store it in a Table DAT for easy editing.

<Admonition type="dyk" title="Did you know? · 1970s preset memory">
The earliest commercial show-control desks — Strand's *Mini Light Palette* (1976) and similar — had 99 preset memory slots, each storing 64 channel values. The architectural pattern (snapshot, save, recall, crossfade) was already mature when MIDI was invented seven years later. Lighting designers, theatre, dance, opera — all have used preset banks for fifty years. TouchDesigner is the digital-art descendant of the same tradition [1].
</Admonition>

## Part 2 — Save and recall via Script DAT <a id="part-2"></a>

A Script DAT with two callbacks — `onSavePreset(slot)` and `onRecallPreset(slot)` — implements the preset system in 30 lines.

<CodeBlock lang="python" file="preset_dat.py">
```python
import json

# preset_list = list of (operator_path, parameter_name) tuples
PRESET_LIST = [
    ('/visuals/noise1', 'period'),
    ('/visuals/blur1', 'size'),
    ('/visuals/level1', 'bright'),
    ('/visuals/level1', 'contrast'),
    ('/audio/lookup1', 'amount'),
]

def onSavePreset(slot):
    preset = {}
    for op_path, par_name in PRESET_LIST:
        node = op(op_path)
        if node is None:
            continue
        value = getattr(node.par, par_name).eval()
        preset[f'{op_path}.{par_name}'] = value
    me.storage[f'preset_{slot}'] = preset
    print(f'Saved preset to slot {slot}')

def onRecallPreset(slot):
    preset = me.storage.get(f'preset_{slot}')
    if preset is None:
        print(f'Slot {slot} is empty')
        return
    for key, value in preset.items():
        op_path, par_name = key.rsplit('.', 1)
        node = op(op_path)
        if node is None:
            continue
        setattr(node.par, par_name, value)
    print(f'Recalled preset from slot {slot}')
```
</CodeBlock>

Wire UI buttons to call these callbacks (button 1 → save, buttons 2-8 → recall slots 1-7) and you have a working 7-slot preset bank.

`me.storage` persists across project reloads, so presets saved in editing survive into performance.

<Admonition type="important">
Store *the parameter value*, not its expression. Recalling a preset should set a numeric value; if a parameter had an expression like `absTime.seconds * 0.1`, the recall step should overwrite the expression. To preserve expressions, save the `.expr` string instead of the eval'd value — but most preset systems do not need this, and the simpler behaviour is usually what you want.
</Admonition>

## Part 3 — Interpolation: fading between presets <a id="part-3"></a>

Snapping between presets is jarring. Most show-control systems support **crossfading** — over `T` seconds, every parameter slides linearly from its current value to the target preset's value.

The implementation: maintain three pieces of state — the start preset (`A`), the target preset (`B`), and a fade time `T`. On `onRecallWithFade(target_slot, fade_time)`, capture the *current* values as `A`, look up the target preset as `B`, then run a per-frame interpolation:

<CodeBlock lang="python" file="crossfade.py">
```python
def onCookEachFrame():
    t = me.fragment.fade_progress  # 0..1 over fade_time seconds
    a = me.fragment.start_values
    b = me.fragment.target_values
    if t >= 1.0:
        # finished — write final values once and stop
        ...
        return
    for key in a:
        path, par_name = key.rsplit('.', 1)
        node = op(path)
        if node is None: continue
        new_val = (1 - t) * a[key] + t * b[key]
        setattr(node.par, par_name, new_val)
```
</CodeBlock>

`me.fragment.fade_progress` is a custom value you advance each frame by `dt / fade_time`. When `t` reaches 1, you stop interpolating and the recall is complete.

Non-numeric parameters (menus, strings) are not linearly interpolable; snap them at the start of the fade or at the end depending on aesthetic.

<Admonition type="note">
For most projects, *exponential* (or *S-curve*) interpolation feels better than linear. Replace `(1 - t) * a + t * b` with `mix(a, b, smoothstep(0, 1, t))` to get the smoothstep curve, which has zero derivative at both endpoints. The fade looks more natural and the parameter does not "stop suddenly."
</Admonition>

## Synthesis project — 8-slot preset bank with crossfade <a id="synthesis"></a>

Build a complete preset system:

1. UI panel with 8 preset slot buttons + 1 save button + 1 fade-time slider.
2. Save button captures current values to whichever slot is currently highlighted.
3. Each slot button recalls its preset over `fade_time` seconds.
4. Visual feedback: the active slot's button lights up; the fading slot's button pulses.
5. Disk persistence: presets saved to `presets.json` next to the project; loaded on startup.

The result is a tool you carry between projects. Drop it in, define your `PRESET_LIST`, and you have working show-control instantly.

**Reflection questions**

- Crossfade interpolation between menu parameters (like Noise type: `random`, `sparse`, `harmonic`) does not work. How would you handle them?
- Your preset save unintentionally captured a parameter that uses an expression (`absTime.seconds * 0.5`). On recall, what happens?
- The fade-in feels "linear and mechanical." What is the smallest change to make it feel "organic"?

<Dropdown summary="Answers">

**Menu parameters** — they are categorical and cannot be linearly interpolated. Snap them at one boundary: either at fade start (so the new mode is active throughout the fade) or fade end (so the old mode persists until the fade completes). Document which you chose.

**Captured expression** — the save step calls `.eval()` and gets the *numerical value at save time*. The recall step sets `.par.X = value`, which overwrites the expression with a static numeric value. The animation stops. To preserve expressions, save `.expr` strings separately and restore them.

**Mechanical feel** — replace linear interpolation with smoothstep: `t' = t*t*(3 - 2*t)`. The fade is zero-derivative at both ends, so parameters ease in and out smoothly. Costs nothing computationally; transforms the feel of the entire system.

</Dropdown>

#### Make it your own

- **MIDI program-change**: a MIDI In CHOP listens for program-change messages; each one recalls the corresponding preset. The bank is now controllable from a hardware MIDI footswitch.
- **Random preset blend**: a "shuffle" button that picks two random presets and crossfades between them over 8 seconds. Useful as ambient background generator.
- **Preset morph**: instead of A → B, do A → B → C → D in a slow loop. A 30-second cycle through 4 presets is the cheapest "ambient generative show" possible.

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

A preset is a key-value snapshot of named parameters. Save and recall are two Script DAT callbacks walking a fixed parameter list. Crossfade interpolation runs per-frame linear (or smoothstep) interpolation between the captured start values and the target preset, over a configurable fade time. Persistence via `me.storage` (in-project) or a JSON file (cross-project) makes presets durable. The preset bank + crossfade + MIDI program-change is the smallest possible show-control system, and it has been the architecture of professional theatre lighting for fifty years. With it, you can hand your TD project to a non-technical operator and they can run a show.

</Admonition>

**Common pitfalls to avoid**

- Saving every parameter on every operator. Built-in parameters (Display, Cook Type) should not be in presets.
- Linear interpolation everywhere. Use smoothstep for visual continuity.
- Forgetting that menu and string parameters cannot interpolate. Snap them; do not pretend.
- Storing preset data in DAT cells. Use `me.storage`.
- No preset save/load file path discipline. Hard-coding `C:/My/Documents` breaks on every other machine.
