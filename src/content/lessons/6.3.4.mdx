## Overview <a id="overview"></a>

A *material* in modern rendering is a stack of procedural layers — base colour, normal map, roughness, displacement — that together describe how a surface looks under light. The 2D version covers the most important layer: the **albedo**, or what the surface looks like when lit flatly. This lesson builds one material from scratch — rust on weathered iron — by combining three procedural primitives from this module: Worley cracks (6.1.3), fbm mottling (6.1.1), and a two-stop colour ramp (6.3.1). The same recipe — cells + noise + palette — produces lichen, concrete, weathered wood, ageing copper, and every other "lived-in" surface [1].

### Learning objectives

<ol class="obj-list">
  <li>Compose Worley cellular noise + fbm mottling + a colour ramp into a layered material.</li>
  <li>Use the `F₂ − F₁` Worley map as a crack-line mask laid over the base material.</li>
  <li>Tune layer weights and palette colours to shift between fresh paint, mature rust, and corroded iron.</li>
  <li>Extend the stack to other materials by swapping the palette and tuning the noise scales.</li>
</ol>

## Quick start — rust on iron <a id="quick-start"></a>

<CodeBlock lang="python" file="quick_start.py">
```python
import numpy as np
from PIL import Image
# fbm() from 6.1.1, worley distances from 6.1.3 — assume both helpers in scope

H, W = 400, 400

# Layer 1: base fbm mottling
base = fbm((H, W), scale=70, octaves=5, seed=7 + 110)

# Layer 2: Worley cracks (F2 - F1)
rng = np.random.default_rng(7 + 111)
seeds = rng.integers(0, [H, W], size=(60, 2))
y, x = np.indices((H, W))
dy = y[..., None] - seeds[:, 0]; dx = x[..., None] - seeds[:, 1]
sorted_d = np.sqrt(np.sort(dy*dy + dx*dx, axis=-1))
crackle = sorted_d[..., 1] - sorted_d[..., 0]
crackle = crackle / crackle.max()
crack_mask = crackle < 0.04        # thin cracks

# Layer 3: two-stop rust palette
rust_dark = np.array([0.45, 0.18, 0.08])
rust_light = np.array([0.85, 0.45, 0.20])
rgb = base[..., None] * rust_light + (1 - base[..., None]) * rust_dark

# Paint cracks dark on top
rgb[crack_mask] = [0.10, 0.07, 0.05]

Image.fromarray((np.clip(rgb, 0, 1) * 255).astype(np.uint8)).save('rust_material.png')
```
</CodeBlock>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — Layer 1 is colour, layer 2 is detail

Procedural materials are *layered*. The bottom layer determines the bulk colour and broad-scale texture; each subsequent layer adds finer detail. The recipe for rust:

```python
# Layer 1 — broad rust mottling: which patches are bright orange, which dark brown
base = fbm(scale=70)               # smooth field at the mottling scale

# Layer 2 — fine crack network: thin dark lines from the Worley F2 - F1 map
crackle = worley_F2_minus_F1(seeds)
crack_mask = crackle < threshold   # thin lines

# Layer 3 — palette: map base to a two-stop rust ramp, then darken at the cracks
rgb = palette_lerp(base, rust_dark, rust_light)
rgb[crack_mask] = [0.10, 0.07, 0.05]
```

The order matters: cracks paint *on top* of the base mottling because they should be visible regardless of underlying rust colour. If the order were reversed, the cracks could be hidden by bright rust patches [2].

### Concept 2 — Worley cracks as a thin mask

The `F₂ − F₁` Worley field from 6.1.3 measures "distance to second-nearest seed minus distance to nearest seed." It's near 0 on cell boundaries (where two seeds tie for closest) and grows quickly as you move into a cell. Thresholding at a small value picks the boundary pixels:

```python
crack_mask = crackle < 0.04
```

A threshold of 0.04 gives lines roughly 1–2 pixels wide. Tuning the threshold tunes the crack width — 0.02 gives near-1-pixel-wide cracks; 0.10 gives broad blocks of dark.

For *unaligned* cracks (cracks that don't follow the Worley cells), you can use an fbm field thresholded at its low-density tail instead. The Worley version gives architecturally-plausible cracks that look like a rust network rather than random scribbles [3].

### Concept 3 — The palette is the material's identity

Same noise layers, different palettes → different materials. The stack from the quick start is shape-agnostic:

| Material | Layer 1 stop A | Layer 1 stop B | Crack colour |
|----------|----------------|----------------|--------------|
| Rust     | `(0.85, 0.45, 0.20)` | `(0.45, 0.18, 0.08)` | `(0.10, 0.07, 0.05)` |
| Concrete | `(0.85, 0.85, 0.82)` | `(0.55, 0.55, 0.52)` | `(0.25, 0.25, 0.22)` |
| Lichen   | `(0.55, 0.65, 0.30)` | `(0.30, 0.35, 0.15)` | `(0.10, 0.15, 0.05)` |
| Copper patina | `(0.50, 0.70, 0.60)` | `(0.30, 0.50, 0.40)` | `(0.10, 0.20, 0.15)` |

The palette swap is the most economical way to extend the material library. Pick a real-world reference photo, sample two representative colours, and you have a procedural version of that material [4].

<Admonition type="dyk" title="Technical note · why layered procedurals beat hand-painted textures">
Production game and film pipelines have largely shifted from hand-painted to procedural texturing because procedural materials are *resolution-independent* and *seamlessly tileable*. A hand-painted texture has a fixed resolution and tiles awkwardly; a procedural one re-evaluates to any resolution and naturally wraps when you set the noise functions to be periodic. Substance Designer (Adobe) is the industry-standard tool for layered procedural materials; its building blocks are the same primitives we've covered in this module [5].
</Admonition>

<Exercise n={1} kicker="EXECUTE" title="Render the rust material">

Run `material.py` from the quick start.

**Reflection questions**

- Why does layering the cracks *after* the base produce convincing rust, whereas other orderings might not?
- What happens if you bump the Worley seed count from 60 to 200?
- What's the role of `clip` in the final RGB conversion?

<Dropdown summary="Answers">

**Crack order** — cracks need to be the visible surface feature. If you painted the base over the cracks, half the cracks would be hidden. The convention in procedural materials is "top-down" — surface details on top, deeper structures underneath.

**More seeds** — finer crack network. The rust looks more weathered; each rust patch becomes its own micro-island.

**Clip** — the palette lerp can produce values slightly above 1 if `base` exceeds 1 (numerical drift in fbm). `np.clip(0, 1)` keeps the RGB conversion safe.

</Dropdown>

</Exercise>

<Dropdown summary="Complete solution">

<CodeBlock lang="python" file="exercise3_solution.py">
```python
import numpy as np
from PIL import Image
# fbm() in scope

H, W = 250, 250

def render(palette_a, palette_b, crack_color, crack_seeds, crack_thresh):
    base = fbm((H, W), scale=70, octaves=5, seed=11)
    rng = np.random.default_rng(22)
    pts = rng.integers(0, [H, W], size=(crack_seeds, 2))
    y, x = np.indices((H, W))
    dy = y[..., None] - pts[:, 0]
    dx = x[..., None] - pts[:, 1]
    sd = np.sqrt(np.sort(dy*dy + dx*dx, axis=-1))
    crackle = sd[..., 1] - sd[..., 0]
    crackle = crackle / crackle.max()
    mask = crackle < crack_thresh
    rgb = base[..., None] * palette_b + (1 - base[..., None]) * palette_a
    rgb[mask] = crack_color
    return np.clip(rgb, 0, 1)

fresh  = render(np.array([0.25, 0.45, 0.55]),
                np.array([0.45, 0.65, 0.75]),
                [0.15, 0.25, 0.30], 20, 0.02)
middle = render(np.array([0.55, 0.30, 0.15]),
                np.array([0.80, 0.50, 0.25]),
                [0.20, 0.10, 0.05], 40, 0.03)
mature = render(np.array([0.45, 0.18, 0.08]),
                np.array([0.85, 0.45, 0.20]),
                [0.10, 0.07, 0.05], 60, 0.04)

gap = np.zeros((H, 8, 3))
timeline = np.hstack([fresh, gap, middle, gap, mature])
Image.fromarray((timeline * 255).astype(np.uint8)).save('rust_timeline.png')
```
</CodeBlock>

**How it works:**

- The `render` function takes palette + crack parameters and returns an RGB image.
- Three calls produce three "ages": fresh paint (cool palette, few cracks), middle (warm with moderate cracks), mature (rust palette, dense cracks).
- The hstack timeline lets you read the progression at a glance.

</Dropdown>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

A procedural material stacks small primitives into a credible surface. The recipe — base fbm mottling + Worley `F₂ − F₁` crack mask + two-stop palette ramp — produces rust, concrete, lichen, copper patina, and any "weathered" material. Layer order matters: cracks paint on top of the mottling so the surface details remain visible regardless of base colour. The palette is the material's identity — swap two colours and you have a different material with the same noise structure. The same compositional approach scales to production tools (Substance Designer, shaders) where you stack dozens of primitives instead of three. The principle stays: every material is a *stack*; build it from one-line primitives.

</Admonition>

**Common pitfalls to avoid**

- Painting the base over the cracks instead of after — cracks become invisible in bright regions.
- Setting the crack threshold too high — cracks become broad blocks instead of thin lines.
- Using a single colour stop instead of two — the material loses its "mottled" feel and looks flat.
- Forgetting to normalise the `F₂ − F₁` field before thresholding — different runs have different effective thresholds.
- Reusing the same fbm seed for base and cracks — both layers correlate, killing the procedural variety.
