## Overview

You may need less than you expect. In Modules 0 to 8, a lesson's Run button runs its script inside your browser, so reading and running need no install at all [1]. You need Python on your computer when you want to edit a script, which is what the Modify and Create exercises ask for, and later modules need more.

| To do this | You need |
|---|---|
| Read any lesson; press Run in Modules 0 to 8 | A browser |
| Edit and write scripts, in any module | Python and the core kit |
| Module 10 | TouchDesigner as well |
| Module 11 | The camera kit as well, and a webcam |
| Module 12 | The model kit as well. A GPU helps a lot |

## Quick start — try it on this page <a id="quick-start"></a>

Press Run. This script reports its Python version and makes an image, with nothing installed.

<CodeBlock lang="python" file="0.3_quick_start.py">
```python
import sys

import numpy as np
from PIL import Image

print(f"Python {sys.version.split()[0]}, NumPy {np.__version__}")

# An image is a grid of numbers. This one holds 256 greys, dark on the left.
gradient = np.linspace(0, 255, 256, dtype=np.uint8)
image = np.tile(gradient, (80, 1))

Image.fromarray(image).save("first_image.png")
print("Saved first_image.png")
```
</CodeBlock>

<Download href="/lesson-media/Module_00_foundations_definitions/0.3_setup_environment/0.3_quick_start.py" label="0.3_quick_start.py — this script" />

The first press takes a few seconds while your browser fetches Python. That copy of Python belongs to the page, so the version it prints may be newer than the 3.11 you would install below. If all you want for now is to read and run, you can stop here and go on to [lesson 1.1.1](/lessons/1.1.1).

## Part 1 — Install Python 3.11 <a id="part-1"></a>

The course's scripts are tested on Python 3.11, and every kit below installs on it. Version 3.11.9 is the last 3.11 release with installers for Windows and macOS [2], and 3.11 is due to receive security fixes until about October 2027 [3].

1. Open the [Python 3.11.9 download page](https://www.python.org/downloads/release/python-3119/) and pick the installer for your system. The page points you to newer 3.11 releases, but those come as source code only, so stay on 3.11.9.
2. On Windows, tick **Add python.exe to PATH** on the installer's first screen.
3. On Linux, use your package manager or a version manager such as pyenv, since this release offers no Linux installer. Debian and Ubuntu may also need the `python3.11-venv` package for the next step.
4. Open a new terminal (PowerShell on Windows, Terminal on macOS) and check the version with `py -3.11 --version` on Windows or `python3.11 --version` on macOS and Linux.

It should print a version starting with 3.11. You can keep other Python versions installed alongside it.

## Part 2 — A folder and a virtual environment <a id="part-2"></a>

Packages installed into your computer's main Python can clash with other programs that rely on different versions. A virtual environment avoids that: it is a folder with its own Python and its own packages [4]. What you install for this course stays inside it, and if anything goes wrong you can delete the folder and start again.

<Figure
  src="/lesson-media/Module_00_foundations_definitions/0.3_setup_environment/what_a_venv_keeps_apart.png"
  alt="A diagram of a computer containing the system Python, left alone, and a course folder. The course folder holds a .venv folder with its own Python and packages, next to your scripts and images."
  caption="The course's packages stay in .venv, inside your course folder."
  num={2}
  role="diagram"
/>

Run these once. On Windows, in PowerShell:

<CodeBlock lang="powershell">
```powershell
mkdir pixels2genai
cd pixels2genai
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
```
</CodeBlock>

On macOS or Linux:

<CodeBlock lang="bash">
```bash
mkdir pixels2genai
cd pixels2genai
python3.11 -m venv .venv
source .venv/bin/activate
```
</CodeBlock>

Your prompt now starts with `(.venv)`. Each time you open a new terminal, `cd` into the folder and run the last line again.

<Dropdown summary="Windows says running scripts is disabled">

PowerShell blocks scripts by default on some computers. Python's documentation gives this command, which allows local scripts for your user account [4]. Run it once, then activate again:

<CodeBlock lang="powershell">
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```
</CodeBlock>

</Dropdown>

## Part 3 — Install what you need <a id="part-3"></a>

A requirements file lists packages for pip to install in one go [5]. Download the core kit, move the file from your Downloads folder into `pixels2genai`, then run the command below with `(.venv)` showing. It downloads about 125 MB, so allow a few minutes.

<Download href="/lesson-media/Module_00_foundations_definitions/0.3_setup_environment/0.3_requirements-core.txt" label="0.3_requirements-core.txt — core kit" />

<CodeBlock lang="bash">
```bash
python -m pip install -r 0.3_requirements-core.txt
```
</CodeBlock>

That covers NumPy for arrays [6], Pillow for images [7], and the other packages the scripts in Modules 0 to 10 import. Leave the rest until you reach their modules:

- **Module 10:** [TouchDesigner](https://derivative.ca/download). Its free Non-Commercial licence allows learning work, with a resolution limit; check the current terms on Derivative's page [8].
- **Module 11:** the camera kit, for lessons that read a webcam.
- **Module 12:** the model kit, which is large. For an NVIDIA GPU, use the [PyTorch selector](https://pytorch.org/get-started/locally/) in place of this file [9].

<Download href="/lesson-media/Module_00_foundations_definitions/0.3_setup_environment/0.3_requirements-camera.txt" label="0.3_requirements-camera.txt — camera kit" />

<Download href="/lesson-media/Module_00_foundations_definitions/0.3_setup_environment/0.3_requirements-models.txt" label="0.3_requirements-models.txt — model kit" />

If something goes wrong, these are the usual causes:

| What you see | What it means | What to do |
|---|---|---|
| `python` or `py` is not recognised | Python is not on your PATH | Run the installer again, choose **Modify**, and on Advanced Options tick **Add Python to environment variables** |
| `No module named numpy` | The environment is not active | Check for `(.venv)`, then activate it |
| `No such file or directory` | The file or the terminal is in another folder | Move the file into `pixels2genai`, then `cd` there |
| A package will not install | Often the wrong Python version | Run `python --version` with `(.venv)` showing; it should say 3.11 |

## Summary

<Admonition title="Key takeaways">

- Reading and pressing Run need only a browser in Modules 0 to 8. Editing scripts needs Python.
- Keep the course in its own folder with its own `.venv`, and activate it each time you open a terminal.
- Install kits when you reach their modules.
- Scripts save images to the folder the terminal is in.

</Admonition>
