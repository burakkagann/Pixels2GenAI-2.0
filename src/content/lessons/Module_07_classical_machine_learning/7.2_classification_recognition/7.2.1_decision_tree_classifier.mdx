## Big Question — *can a model be both accurate and human-readable?* <a id="big-question"></a>

Most modern ML models are good at predictions and terrible at explaining themselves. A neural network's forward pass is a tangle of matrix multiplies; "why did it classify this image as a dog?" has no satisfying short answer. **Decision trees** are the opposite. A trained decision tree is a list of yes/no questions: *"Is feature 0 ≤ 0.4? If yes, is feature 1 ≤ -0.2? If yes, class A; if no, class B."* Anyone with five minutes can read it. The interpretability is not a side effect — it is the entire reason trees survived sixty years of ML history, from Hunt's 1962 CLS algorithm [1] to Quinlan's ID3 (1986) and C4.5 (1993) [2] to Breiman's CART (1984) [3], which is the formulation used by scikit-learn today.

The price of human readability is geometric inflexibility. Decision trees can only make axis-aligned cuts; a diagonal pattern in feature space takes a deep tree of staircase steps to approximate. Used alone they tend to overfit. Used as the *base learner* in Random Forests (lesson 7.2.2) and gradient-boosted ensembles (XGBoost, LightGBM, CatBoost), they remain the workhorse of tabular machine learning in 2026.

### Learning objectives

<ol class="obj-list">
  <li>Recognise a trained decision tree as a list of axis-aligned cuts that partition feature space into rectangles.</li>
  <li>Define and compute **Gini impurity** as a node-purity measure; use it as the split-quality criterion.</li>
  <li>Implement the greedy splitting rule: at every node, scan every (feature, threshold) and pick the one that minimises weighted child impurity.</li>
  <li>Diagnose the classic decision-tree failure mode — overfitting at unlimited depth — and apply depth limiting, pruning, or ensembling as fixes.</li>
</ol>

## Part 1 — A tree as a list of questions <a id="part-1"></a>

A decision tree is a binary tree where every internal node holds a single test of the form `feature[j] <= threshold` and every leaf holds a predicted class. Predicting on a new point means walking from the root to a leaf, going left when the test is true and right otherwise.

The geometric translation: each test corresponds to a vertical or horizontal cut in feature space. The set of leaves is a partition of feature space into axis-aligned rectangles (in 2D — into axis-aligned boxes in higher dimensions). Each rectangle gets one predicted class. That is the entire model.

<Admonition type="dyk" title="Did you know? · MD3 and the Sensors Lab">
The 1979 MEDAS expert system at Brigham Young University used a hand-built decision tree to diagnose cardiac chest pain in real time, walking the patient through 30 yes/no questions in under five minutes. It was one of the first deployed expert systems in clinical practice. The system stayed in use until the late 1990s, long after neural networks had been promoted as the future of medical AI [4].
</Admonition>

## Part 2 — Gini impurity and the greedy split <a id="part-2"></a>

How does the algorithm pick which question to ask at each node? The answer is a **purity score**: a measure of how *mixed* a set of labels is. The most common choice is **Gini impurity**:

`G(S) = 1 - Σ_c p_c²`

where `p_c` is the fraction of points in `S` with class `c`. A perfectly pure set (one class only) has `G = 0`; a 50/50 binary mix has `G = 0.5`; a uniform 3-class mix has `G = 0.67`. Lower Gini means purer.

<CodeBlock lang="python" file="gini_demo.py">
```python
def gini(y):
    _, counts = np.unique(y, return_counts=True)
    p = counts / counts.sum()
    return 1.0 - (p * p).sum()
```
</CodeBlock>

The **best split** at a node is the (feature, threshold) pair that minimises the *weighted average Gini* of the two children:

`weighted_score = (|L| · G(L) + |R| · G(R)) / |S|`

This is greedy — it picks the locally best split without looking ahead — and is optimal for a single node but not for the tree as a whole.

<CodeBlock lang="python" file="best_split_demo.py">
```python
def best_split(X, y):
    best = (None, None, float('inf'))
    for j in range(X.shape[1]):
        for v in np.unique(X[:, j]):
            mask = X[:, j] <= v
            left, right = y[mask], y[~mask]
            if len(left) == 0 or len(right) == 0:
                continue
            score = (len(left) * gini(left) + len(right) * gini(right)) / len(y)
            if score < best[2]:
                best = (j, v, score)
    return best[:2]
```
</CodeBlock>

`O(n × d × n)` per node where `d` is the number of features — quadratic in `n`. Practical implementations sort each feature once and then process splits in sorted order in `O(n log n)` per feature. The cost compounds with depth, so for huge datasets you use ensemble methods (Random Forests) that build many shallow trees instead of one deep one.

<Admonition type="important">
**Information gain** (used by Quinlan's ID3/C4.5) is an alternative split criterion based on entropy instead of Gini. The two produce nearly identical trees on most data; Gini is computationally cheaper because it has no logarithm. Default to Gini unless you have a specific reason to switch.
</Admonition>

## Part 3 — Depth, overfitting, and the case for ensembles <a id="part-3"></a>

With no depth limit, a decision tree will grow until every leaf is pure — i.e., until it has memorised every training point exactly. Train accuracy: 100%. Test accuracy: usually mediocre. The tree has captured the noise as well as the signal. Look at the third panel of Figure 1 — at unlimited depth the boundaries are wiggly fragments that pass through single training points. That is overfitting.

Three standard fixes:

1. **Pre-pruning**: set a maximum depth (`max_depth=3` or `=5`), a minimum number of samples per leaf (`min_samples_leaf=20`), or a maximum number of leaves.
2. **Post-pruning**: build the full tree, then prune away subtrees whose removal increases validation accuracy.
3. **Ensembling**: build many shallow trees on random sub-samples of the data and average their predictions. This is exactly the Random Forest idea (lesson 7.2.2).

The intuition behind ensembling: a single shallow tree has high bias (cannot fit complicated boundaries) but low variance (different training sets give similar trees). A single deep tree has low bias but high variance. Averaging many deep trees reduces variance while keeping bias low — best of both worlds, at the cost of losing the "human-readable" advantage [3].

<Admonition type="note">
The transition from "single interpretable tree" to "ensemble of opaque trees" is the central trade-off in this subtopic. You can have **interpretable**, or you can have **accurate on real data**, but tree-based ML usually cannot have both at the same time. Linear models and rule lists (RuleFit, Falling-Rule Lists) are alternative ways to keep interpretability; they sacrifice some accuracy on complex datasets.
</Admonition>

**Reflection questions**

- Look at the depth-1 panel. What is the single best yes/no question to ask about this dataset?
- The unlimited-depth panel has train accuracy 1.00, but its test accuracy would be lower. Why?
- The decision boundaries are all vertical or horizontal lines. What if the true boundary in feature space is a diagonal?

<Dropdown summary="Answers">

**Depth-1 best question** — the algorithm picked whichever feature/threshold separates the two largest classes best. For three classes, depth 1 can never give better than a 50%-ish baseline because you can only express two final classes with one split. That is why the depth-1 panel shows poor accuracy — the limit is structural, not parametric.

**Train 1.00, test < 1.00** — the tree memorised every training point including its label noise. On unseen points the memorised noise rules do not generalise; only the consistent structure does. The gap between train accuracy and test accuracy is overfitting, the canonical ML failure mode.

**Diagonal boundary** — a single diagonal boundary takes many axis-aligned staircase steps to approximate well. Each step requires a new split. The tree's depth grows proportionally to the resolution you want for the diagonal — and so does its tendency to overfit. The fix: rotate the data (which a decision tree cannot do), or use a model with a more flexible inductive bias (SVM with RBF kernel — lesson 7.2.3).

</Dropdown>

- **Train on a real dataset** like the UCI Iris dataset, the Wine dataset, or the Adult Income dataset. Plot the trained tree with `plot_tree` and see if the rules match domain intuition.

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

A decision tree is a list of yes/no questions that partitions feature space into axis-aligned rectangles. Training uses greedy splitting: at each node, scan every (feature, threshold) and pick the one that minimises weighted child Gini impurity. Without depth limiting, trees overfit by memorising training noise. Three fixes: prune the tree, limit its depth, or build an ensemble. The interpretability is the entire reason single trees survived; the geometric inflexibility is the reason they are usually used inside ensembles in 2026. Random Forests (next lesson) and gradient boosting are the practical descendants.

</Admonition>

**Common pitfalls to avoid**

- Reading too much into a single tree as "the truth." Different random samples produce different trees — the structure is not stable.
- Comparing trees built on the same data with different `random_state` and claiming the algorithm is non-deterministic. It is deterministic given a tie-breaking rule; the rule depends on `random_state` for ties.
- Using a tree on data where one feature has a much larger numeric range than the others. Trees do not need standardisation, but features with categorical encoding can cause unstable splits.
- Skipping cross-validation. Tree-based models are highly sensitive to depth and sample-leaf settings; always tune on a validation set.
- Forgetting that decision trees handle missing data only in some libraries (sklearn requires you to impute manually; XGBoost handles missing values natively).
