## Big Question — *why does averaging many overfit models often beat any single carefully-tuned one?* <a id="big-question"></a>

A single decision tree at full depth memorises its training set — accuracy 100% on data it has seen, much worse on data it has not. The natural fix would be to make the tree shallower. **Random Forests, introduced by Leo Breiman in 2001 [1], do the opposite: keep the trees deep but build hundreds of them, each on a different random subset of the data and features.** The ensemble's prediction is the majority vote. The variance of one tree is high; the variance of an average of N independent trees is roughly N times lower. The bias of each tree is low; the bias of the average is roughly the same. Net result: lower error on unseen data than the best possible single tree.

The two ideas that make it work are **bagging** (Bootstrap AGGregating, due to Breiman in 1996 [2]) and **random subspaces** (Ho 1998 [3]). Bagging samples training data with replacement; random subspaces sample features. Both inject randomness so the trees disagree on details — and in averaging, the disagreements cancel while the consistent signal sums.

## Part 1 — Bias, variance, and the ensemble math <a id="part-1"></a>

The error of any predictor decomposes into **bias** (systematic error: the model class cannot represent the truth), **variance** (the prediction changes a lot with different training data), and irreducible noise. Deep decision trees have low bias and high variance. The variance-reduction property of averaging is elementary statistics:

`Var(mean of N iid trees) = Var(single tree) / N`

The catch is "iid" — independent and identically distributed. In practice your trees are not independent because they are all trained on (slightly different views of) the same data. The actual reduction is less than `1/N`, but it is still significant. Breiman showed that for a forest of trees with pairwise correlation `ρ`:

`Var(forest) = ρ · Var(single tree) + (1 - ρ) · Var(single tree) / N`

The first term is the floor. The two algorithmic ingredients of Random Forests — bootstrapping the data and randomising the feature subset at every split — push `ρ` as close to zero as possible.

<Admonition type="dyk" title="Did you know? · Breiman, Tibshirani, Friedman">
Leo Breiman published the Random Forests paper in 2001 at age 73. By then he had already been a co-author of CART (the original decision-tree formulation), introduced bagging, and chaired Berkeley's statistics department. His core contribution to ML was the recognition that *averaging high-variance models* was systematically more powerful than tuning a single low-variance one — which became the doctrine of every modern ensemble method, including XGBoost and LightGBM [1, 2].
</Admonition>

## Part 2 — Bootstrap sampling and the 63% rule <a id="part-2"></a>

A **bootstrap sample** is N rows drawn with replacement from N rows. Some rows appear multiple times; some not at all. Asymptotically, each row's probability of being missing from a bootstrap sample is

`(1 - 1/N)^N → 1/e ≈ 0.368`

so roughly 63% of the original rows appear in each bootstrap (some multiple times). The 37% left out — called **out-of-bag** (OOB) samples — make a free validation set for that particular tree. Many sklearn classifiers expose an `oob_score_` attribute that aggregates OOB predictions across all trees [4].

<CodeBlock lang="python" file="bootstrap_demo.py">
```python
n = len(X)
idx = rng.integers(0, n, size=n)  # sample with replacement
X_boot, y_boot = X[idx], y[idx]
# unique idx count is typically ~0.63 * n
```
</CodeBlock>

This is the **bagging** ingredient — each tree sees a different slice of the world. With this alone, you get *Bagged Trees*, a slight improvement over a single tree. The bigger improvement comes from also de-correlating *what the trees do with what they see*.

## Part 3 — Random subspaces and feature importance <a id="part-3"></a>

At every split of every tree, instead of considering all `d` features, sample `m = sqrt(d)` (for classification) or `m = d/3` (for regression) of them and pick the best split *among those*. This is the **random subspace** trick. Different trees consider different features at each node, so even with similar bootstrap samples, the trees take different first-split paths and end up structurally different.

<CodeBlock lang="python" file="subspace_demo.py">
```python
for split in tree.splits:
    candidate_features = rng.choice(d, size=int(np.sqrt(d)), replace=False)
    best_feature, best_threshold = best_split(X[:, candidate_features], y)
```
</CodeBlock>

Together, bootstrap + random subspaces push the pairwise correlation `ρ` between trees from ~0.9 (just bagging) down to ~0.5 or less. The variance reduction is dramatic.

A useful by-product: **feature importance**. Count how often each feature is used in splits across the whole forest, weighted by how much each split improves Gini. Features that consistently appear high in trees are the truly informative ones; irrelevant features rarely get picked because random subspaces give them many chances and they rarely produce the best split.

<Admonition type="important">
Feature importance from Random Forests is a *biased* estimator: features with many unique values (continuous features, high-cardinality categoricals) look more important than they are. For unbiased importance, use **permutation importance** — train the forest, then shuffle each feature's values and measure the accuracy drop. Built into sklearn as `permutation_importance`.
</Admonition>

**Reflection questions**

- The single tree in the comparison has 100% train accuracy. The forest has 95% train accuracy but better test accuracy. What is going on?
- Why does Random Forest use sqrt(d) features per split for classification but d/3 for regression?
- Random Forests are sometimes called "embarrassingly parallel." Why?

<Dropdown summary="Answers">

**100% train, lower test: forest 95% train, higher test** — the single tree memorises the noise, including label flips. The forest can never reach 100% train accuracy because each tree only sees a bootstrap sample (some rows are excluded) and is randomised at every split; the ensemble vote cannot produce a perfect match for all training points. That "deliberate underfitting" is what helps it generalise.

**sqrt(d) vs d/3** — empirical defaults found by Breiman. Classification benefits from more aggressive de-correlation (smaller subset → more diverse trees); regression benefits from less, because the prediction is an *average* of continuous values and squashing variance hurts less. Both are heuristics; tune them on validation data.

**Embarrassingly parallel** — every tree is independent of every other tree. You can train 100 trees on 100 CPUs in parallel and the only synchronisation is at the final vote. The `n_jobs=-1` parameter in sklearn uses all available cores. This is one of the simplest "linear scaling" guarantees in ML.

</Dropdown>

#### Make it your own

- **Extra Trees**: replace the per-split best-threshold search with a single random threshold per candidate feature. Faster, slightly less accurate, more biased toward unimportant features. sklearn's `ExtraTreesClassifier`.
- **Gradient Boosting**: instead of training trees independently, train each tree on the *residuals* of the previous ones. Far more accurate but no longer embarrassingly parallel. Implementations: XGBoost, LightGBM, CatBoost. Use these in production tabular ML.
- **Out-of-bag error curve**: train a forest with increasing `n_estimators` and plot OOB error. Should decrease and plateau — gives you the right number of trees without a hold-out validation set.

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

A Random Forest is many overfit decision trees averaged together. Bagging (bootstrap sampling) and random feature subspaces de-correlate the trees so the variance reduction from averaging is real. The result: a model with low bias (deep trees can represent complex boundaries) and low variance (averaging cancels out their idiosyncrasies). Feature importance falls out for free. The price is interpretability — you cannot point to a single rule. For tabular machine learning in 2026, Random Forests and their successor gradient-boosted ensembles remain the strongest off-the-shelf baseline; you switch to neural networks only when you have a lot of data, structured signal (images, audio, text), or a specific architectural reason.

</Admonition>

**Common pitfalls to avoid**

- Treating Random Forest as a black box that "always works." It still needs sensible defaults — particularly `min_samples_leaf` to prevent excessive overfitting per tree.
- Using a forest of N=1 trees and reporting "Random Forest gave 80% accuracy." That is a single tree, not a forest.
- Reading too much into the built-in feature importance. Use permutation importance for anything that matters.
- Training on extremely imbalanced data without `class_weight='balanced'`. The forest will predict the majority class for everything.
- Using Random Forests on time-series data without temporal-aware sampling. Bootstrap sampling assumes iid; time series violate that hard.
