## Big Question — *can we preserve neighbourhoods AND global structure, and do it fast?* <a id="big-question"></a>

t-SNE solved the cluster-separation problem and dominated dimensionality-reduction visualisation for a decade. It also had three persistent weaknesses: it was slow (`O(n²)` even with Barnes-Hut), it destroyed *global* distances (cluster positions relative to each other were meaningless), and it had no `.transform()` for new data. **UMAP — Uniform Manifold Approximation and Projection** — was published by McInnes, Healy & Melville in 2018 [1] and fixed all three within months of release. The mathematical foundation is heavier (Riemannian geometry, fuzzy simplicial sets, algebraic topology of cell complexes), but the practical recipe is the same shape as t-SNE: build a local-neighbour graph in input space, find a low-D embedding whose neighbour graph matches as closely as possible, minimise via gradient descent.

This lesson uses **Isomap** as a stand-in for UMAP because the `umap-learn` package is not in this project's dependencies. The two algorithms differ in their loss function (Isomap minimises geodesic distance MDS; UMAP minimises a cross-entropy between fuzzy simplicial sets) but share the same conceptual core: *the data lives on a manifold; respect the local neighbourhood graph; the rest follows from linear algebra.*

## Part 1 — The manifold hypothesis <a id="part-1"></a>

Take a sheet of paper, roll it into a Swiss roll. Sprinkle 1000 points on it. The points live in 3D, but a single-sheet manifold has intrinsic dimension 2 — you only need two numbers (position along the roll's length, position along the spiral) to identify any point. A linear method like PCA, asked to project to 2D, picks whatever flat plane best fits the cloud's variance — and the spiral structure is destroyed.

**Manifold learning** algorithms recognise that the points are connected by short edges *along the surface* even if they are far apart in 3D. Build the k-nearest-neighbour graph in input space; distances along that graph (geodesic distances on the manifold) are what should be preserved, not the straight-line 3D distances. Isomap [2] did this with classical MDS on the geodesic distance matrix; UMAP does it with a more sophisticated algebraic-topology framework, but the conceptual core is the same.

<CodeBlock lang="python" file="knn_graph_demo.py">
```python
from sklearn.neighbors import NearestNeighbors
nn = NearestNeighbors(n_neighbors=k + 1).fit(X)
distances, indices = nn.kneighbors(X)
# distances[i] = sorted distances to i's k+1 nearest neighbours (incl. itself)
# indices[i] = their indices
```
</CodeBlock>

The manifold hypothesis is empirically true for many high-dimensional datasets: natural images live near a much lower-dimensional manifold; word embeddings live on a manifold whose dimension is much lower than the ambient embedding size. It is false for randomly-sampled high-D data (no structure to discover) and for data with multiple separated manifolds (each needs its own connected component).

<Admonition type="dyk" title="Did you know? · The Whitney embedding theorem">
A k-dimensional manifold can be smoothly embedded in `(2k+1)`-dimensional Euclidean space (Hassler Whitney, 1936). The Swiss roll (`k=2`) fits in 5D; in practice it fits in 3D. This is the theoretical justification for "raise the dimension to embed the manifold flat" — and it is what kernel methods and neural networks both do implicitly [3].
</Admonition>

## Part 2 — UMAP's three improvements over t-SNE <a id="part-2"></a>

**1. Speed.** UMAP's optimisation is stochastic and uses negative sampling (only a few "repulsive" pairs per iteration, not all of them). The result is `O(n^(1.14))` empirical complexity — close to linear. A 100k-point dataset takes a few minutes; t-SNE would take an hour. Modern single-cell genomics with 1M cells uses UMAP routinely [4].

**2. Better global structure.** UMAP's loss is cross-entropy between fuzzy simplicial sets in the input and output. The math is dense, but the visible effect is: clusters of related items often sit near each other in the embedding (semantically related word vectors cluster geographically; cell types from related lineages stay close). t-SNE's local-only optimisation often scrambles cluster positions.

**3. New-data projection.** UMAP fits a reusable model. After training on a dataset, you can call `.transform()` on new points and get embeddings consistent with the training set. This is critical for production pipelines (build the embedding once, deploy it for new inputs). t-SNE is non-parametric and re-runs from scratch for any new dataset.

<Admonition type="important">
UMAP and Isomap have different loss functions — UMAP uses cross-entropy on fuzzy simplicial sets, Isomap uses MDS on geodesic distances — but both rely on the same kNN-graph data structure as input. If you cannot install `umap-learn` (as in this project), Isomap is a reasonable conceptual stand-in for the manifold-preserving idea. For production-quality UMAP you should install `umap-learn` from pip.
</Admonition>

## Part 3 — n_neighbors, min_dist, and the same caveats as t-SNE <a id="part-3"></a>

UMAP has two main hyperparameters:

- **n_neighbors** — the local-neighbourhood size used to build the input-space graph. Small (5–10) preserves fine local detail; large (50–100) preserves coarser global structure. Analogous to t-SNE's perplexity.
- **min_dist** — the minimum distance between embedded points. Small (0.1) gives tight clusters; large (0.5) gives spread-out clusters. Affects only the visual layout; topology is the same.

The same warnings as for t-SNE apply: cluster sizes are not literal, between-cluster distances are *more* meaningful than in t-SNE but still not exact, and the visualisation is qualitative. UMAP plots are excellent for hypothesis generation and for inspection of class structure — they are not input for downstream regression or precise quantification [5].

<Admonition type="note">
A useful heuristic when choosing between PCA / t-SNE / UMAP: PCA when you need a reusable linear projection. t-SNE when you want a quick visualisation and global layout does not matter. UMAP when you want a fast non-linear embedding with somewhat preserved global structure, and especially when you need to embed new data later. For very large datasets (10⁶+) UMAP is the only one of the three that finishes in reasonable time.
</Admonition>

**Reflection questions**

- In the Swiss roll panel, PCA gives a strange-looking 2D layout where colours are mixed. Why?
- The Isomap embedding of the digits has different cluster *positions* from t-SNE's, but the same *cluster identities*. Why is that the expected, not surprising, behaviour?
- Why does UMAP have a `.transform()` for new data while t-SNE does not?

<Dropdown summary="Answers">

**PCA on Swiss roll** — PCA finds the 2D plane of maximum variance. For a Swiss roll, that plane is roughly aligned with the roll's diameter — perpendicular to the spiral axis. Projecting onto it crashes points from opposite arms of the spiral onto each other, mixing colours. The manifold information is destroyed precisely because PCA does not know about local connectivity.

**Different positions, same identities** — both algorithms agree on which points are *neighbours* (because both build the same kNN graph). They disagree on where to put the resulting clusters in 2D because they have different loss functions. The agreement on topology is meaningful (the data has structure both algorithms can find); the disagreement on placement is not meaningful (no objectively "right" placement exists).

**UMAP `.transform()`** — UMAP fits a reusable representation of the input-space manifold and the embedding's relationship to it. New points get mapped onto the manifold (via their kNN in the training set) and then to 2D. t-SNE's loss has no parametric form — it is a function of all pairwise probabilities — so adding a new point would require re-running the entire optimisation. The architectural difference between "parametric" and "non-parametric" dimensionality reduction.

</Dropdown>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

UMAP is a fast, parametric, non-linear dimensionality-reduction method built on the manifold hypothesis: high-dimensional data is approximately concentrated on a much lower-dimensional surface, and the local neighbour graph captures the topology. UMAP and the related Isomap, LLE, and Laplacian Eigenmaps all share that kNN-graph data structure. Compared to t-SNE: faster, better at preserving global structure, supports projecting new data. Compared to PCA: non-linear, can unroll curved manifolds. The same scepticism about quantitative cluster claims applies — UMAP is for exploration, not for downstream metrics. For modern dimensionality-reduction tasks with > 10⁴ points, UMAP is the default 2026 choice; for smaller datasets t-SNE and Isomap remain reasonable.

</Admonition>

**Common pitfalls to avoid**

- Treating UMAP cluster shapes as literal. Same caveats as t-SNE.
- Forgetting to standardise features when they have different scales. Distance-based algorithms care about scaling.
- Using UMAP coordinates as input to a downstream regression. The coordinates are an embedding for visualisation, not a feature space.
- Running UMAP with `n_neighbors = 2` and getting a fragmented embedding. The local graph becomes disconnected and the algorithm cannot recover global structure.
- Picking a single random seed. UMAP, like t-SNE, is non-convex; run a few times to check stability.
