## Big Question — *what does it mean to "see" high-dimensional structure?* <a id="big-question"></a>

A 64-dimensional dataset of hand-drawn digits — every image is an 8×8 grid of grey values — has structure. Eights cluster together; ones cluster together; eights look more like sixes than like ones. But 64 dimensions cannot be plotted. PCA can collapse them to 2D, but it does so by *preserving variance* along straight lines, which captures global axes but not local neighbourhood structure. **t-SNE** (Laurens van der Maaten & Geoffrey Hinton, 2008 [1]) asks the opposite question: *find a 2D embedding such that the probability that point i picks point j as its neighbour is as similar as possible to the same probability in the original high-D space.* The result is the algorithm that produced the famous "MNIST manifold" image — ten clean digit clusters, beautifully separated, that you have seen on every ML blog since 2010.

The price: t-SNE is **non-linear, non-parametric, non-deterministic, and slow**. It cannot project new data without re-fitting; distances between clusters in the embedding are not meaningful; results depend on the `perplexity` hyperparameter and the random seed. It is the right tool for *exploratory visualisation* of high-dimensional data, and a wrong tool for almost everything else. Knowing the difference is the entire pedagogical point.

## Part 1 — Similarity as probability <a id="part-1"></a>

The conceptual move that distinguishes t-SNE from earlier non-linear methods: instead of preserving exact distances, preserve the *probability that point j is a neighbour of point i*. In the high-D input space, define a Gaussian-kernel similarity:

`p_{j|i} = exp(-||x_i - x_j||² / 2σ_i²) / Σ_{k ≠ i} exp(-||x_i - x_k||² / 2σ_i²)`

The bandwidth `σ_i` is chosen per-point so that the effective number of neighbours — the **perplexity** — equals a user-specified value (typically 30). In the low-D embedding space, define a Student-t similarity (1 degree of freedom, equivalent to a Cauchy kernel):

`q_ij = (1 + ||y_i - y_j||²)⁻¹ / Σ_{k ≠ l} (1 + ||y_k - y_l||²)⁻¹`

The t-SNE objective is to make `Q` as close to (the symmetrised) `P` as possible. The "closeness" measure is **Kullback-Leibler divergence** `KL(P || Q)`, which is non-negative and zero iff `P = Q`. Gradient descent on `KL(P || Q)` finds the embedding [1].

<Admonition type="dyk" title="Did you know? · van der Maaten and Hinton">
t-SNE's original paper has 30,000+ citations; van der Maaten was Hinton's postdoc when they wrote it. The 'Student-t' part was the breakthrough — earlier methods (SNE, Hinton & Roweis 2002) used Gaussians on both ends and could not separate distant clusters cleanly. The heavy tail of the Student-t lets the embedding pack closely-related points tightly *without* having to pack the unrelated ones too — solving the "crowding problem" that plagued every earlier non-linear method [1, 2].
</Admonition>

## Part 2 — Why the Student-t? <a id="part-2"></a>

The crowding problem: in `d` dimensions, the volume of a sphere of radius `r` grows as `r^d`. There is exponentially more room for "far away" points than "nearby" points. When you project from high-D into 2D, you have to *compress* this volume difference somehow. With Gaussian similarities on both ends, the algorithm tries to preserve the *exact* probability ratios and ends up squashing distant points onto the boundary — creating one big amorphous blob.

The Student-t kernel has *heavy tails*. Pairs of points at moderate distance get a similar similarity score whether they are 5 units or 50 units apart. The algorithm then has freedom to push very-related points tightly together (where the Student-t is steep) and let everything else spread out into the heavy tail (where the Student-t is nearly flat). The visible effect: clean cluster separation [1].

<CodeBlock lang="python" file="kernel_demo.py">
```python
def joint_q_probabilities(Y):
    sq = ((Y[:, None] - Y[None, :]) ** 2).sum(axis=-1)
    inv = 1.0 / (1.0 + sq)
    np.fill_diagonal(inv, 0)
    return inv / inv.sum()
```
</CodeBlock>

That five-line function is the heart of t-SNE. Gradient descent on `KL(P || Q)` then moves each `y_i` toward "attractive" partners (high `p_ij`) and away from "repulsive" non-partners (low `p_ij`). Convergence usually takes 500–2000 iterations.

<Admonition type="important">
t-SNE's gradient computation is `O(n²)`. The Barnes-Hut acceleration (used in sklearn for `n > ~1000`) approximates the repulsive forces via a quadtree, dropping the cost to `O(n log n)` [2]. For very large `n` ( > 100k ) use FFT-accelerated `openTSNE` or switch to UMAP (lesson 7.3.3).
</Admonition>

## Part 3 — How to read a t-SNE plot, and what not to read <a id="part-3"></a>

A t-SNE plot is a *qualitative* visualisation tool. It tells you the *topology* of high-dimensional structure — what is connected to what, what is separated from what — but it lies systematically about *quantities*. Three things you should never extract from a t-SNE plot:

**1. Cluster sizes are not meaningful.** A tight cluster of 1000 nearly-identical points and a loose cluster of 100 spread-out points can look the same size. The embedding's spatial extent is a function of within-cluster perplexity adaptation, not of true cluster cardinality.

**2. Distances between clusters are not meaningful.** Two clusters that look 5 units apart in the embedding could be much closer or much further in the original feature space than two clusters that look 50 units apart. The algorithm explicitly does not preserve global distances.

**3. The shape of a cluster is not informative.** A circular cluster could be a sphere in feature space; an elongated cluster could be too; an L-shape could be three separate populations. Cluster *shapes* in t-SNE are emergent properties of the optimisation, not of the data.

What t-SNE plots *are* good for: confirming that classes separate, finding anomalies (single points away from any cluster), inspecting whether your representation has captured the structure you care about. They are not good for: clustering (use DBSCAN), quantitative claims, or input to downstream ML (t-SNE distances are not Euclidean in any meaningful sense) [3].

<Admonition type="note">
The "10 digit clusters" figure has become so iconic that people sometimes confuse "we found nice clusters" with "the data is well-separated in 64-D." A t-SNE plot showing 10 clusters could come from 10 well-separated 64-D distributions, but it could also come from 10 mildly-separated ones — the optimisation amplifies whatever separation exists. Run a quantitative clustering (k-NN classifier accuracy on the raw 64-D vectors, say) to corroborate.
</Admonition>

**Reflection questions**

- In the perplexity sweep, which value looks "best"? What does "best" even mean in this context?
- You re-run t-SNE with a different `random_state` and the clusters end up in different positions on the plot. Is this a problem?
- Why is it pointless to run t-SNE on a 2-dimensional dataset?

<Dropdown summary="Answers">

**Best perplexity** — depends on what you want to see. Small perplexity (5) is good for finding fine sub-structure within classes. Large perplexity (60+) is good for getting a clean global layout. The standard recommendation is to *sweep* perplexity across a few values and present whichever visualisation best supports the analytical point you are trying to make. There is no objectively correct value — and there is no objectively correct *t-SNE plot*.

**Different `random_state`, different positions** — not a problem; *expected*. t-SNE optimises a non-convex objective with random initialisation, and the result has no "canonical" rotation or reflection. The *topology* — which points are near which others — is stable across seeds (within tolerance). The *placement* on the page is not.

**2D input** — t-SNE solves the problem "find a low-D embedding that preserves neighbourhoods of a high-D space." If your input is already 2D, the identity map preserves neighbourhoods perfectly. Running t-SNE just adds noise.

</Dropdown>

#### Make it your own

- **t-SNE on word embeddings**: take a pre-trained word2vec or GloVe corpus and project the top-1000 vectors. Semantically similar words cluster — "king-queen-prince" near each other, "dog-cat-pet" elsewhere. The standard demonstration that embeddings carry semantic structure.
- **Colour by metadata**: use the same t-SNE coordinates but colour points by a *secondary* variable (acquisition date, author, lab). If the colours correlate with the t-SNE layout, you have a batch effect.
- **Run twice on the same data**: compare. Cluster topology should be stable; orientation will not be. Useful intuition pump for the "no canonical embedding" property.

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

t-SNE projects high-dimensional data into 2D by matching pairwise neighbour probabilities — Gaussian similarities in the input, Student-t similarities in the embedding. The heavy-tailed kernel solves the crowding problem that earlier non-linear methods suffered. Perplexity controls the effective neighbourhood size and is the algorithm's main hyperparameter. The output is a beautiful visualisation tool for class separation and topology, and a terrible tool for quantitative analysis: cluster sizes, between-cluster distances, and cluster shapes are not meaningful. Use t-SNE for exploration, sanity-checking, and publication figures — not as input to downstream ML.

</Admonition>

**Common pitfalls to avoid**

- Reading cluster sizes or between-cluster distances as meaningful. They are not.
- Using t-SNE coordinates as input to clustering or classification. The coordinates are not a Euclidean embedding.
- Picking a single perplexity. Always sweep across a few values.
- Running t-SNE on already low-dimensional data. There is nothing to compress.
- Trying to project new data after fitting t-SNE on the training set. There is no `.transform()`; t-SNE is non-parametric. Use UMAP (next lesson) if you need that property.
