## Overview <a id="overview"></a>

Diffusion-limited aggregation (DLA) is the fractal that physics produces by accident. Witten and Sander proposed the model in 1981 to explain electrochemical deposition patterns: a particle wanders randomly through a fluid until it touches an existing cluster, at which point it sticks irreversibly. Run that rule many times and the cluster grows outward in a branching dendrite — the same shape mineralogists call "manganese dendrites" on slate, electrochemists call "electrodeposition," and physicists measure to have fractal dimension $D \approx 1.71$ in 2D, independent of every microscopic detail of the experiment [1].

DLA is the natural counterpart to the recursive constructions we have seen so far in Module 04. The Sierpinski triangle (4.1.5) emerged from three contractions applied repeatedly. The Mandelbrot set (4.1.3) emerged from a deterministic quadratic iteration. DLA emerges from a **stochastic** rule with no contractions and no iteration formula — just a million random walks aggregating into one shape — and yet the result is unmistakably fractal. The same algorithm shows up in models of urban sprawl, neuron growth, river-delta formation, and even galaxy clustering [2]. **The geometry is universal; the substrate is incidental.**

## Quick start — single-seed dendrite <a id="quick-start"></a>

<CodeBlock lang="python" file="quick_start.py">
```python
import numpy as np
from PIL import Image

SIZE, N = 600, 4000
rng = np.random.default_rng(3)

cluster = np.zeros((SIZE, SIZE), dtype=np.int32)
cx, cy = SIZE // 2, SIZE // 2
cluster[cy, cx] = 1
max_r = 5

for k in range(2, N + 1):
    launch_r = max_r + 10
    kill_r = launch_r + 30
    angle = rng.uniform(0, 2*np.pi)
    x = int(cx + launch_r * np.cos(angle))
    y = int(cy + launch_r * np.sin(angle))

    while True:
        s = rng.integers(0, 4)
        x += (1, -1, 0, 0)[s]; y += (0, 0, 1, -1)[s]
        if (x - cx)**2 + (y - cy)**2 > kill_r**2 or x < 1 or x >= SIZE-1 or y < 1 or y >= SIZE-1:
            # Walker strayed too far; restart it on the launch circle.
            angle = rng.uniform(0, 2*np.pi)
            x = int(cx + launch_r * np.cos(angle))
            y = int(cy + launch_r * np.sin(angle))
            continue
        if cluster[y-1, x] or cluster[y+1, x] or cluster[y, x-1] or cluster[y, x+1]:
            cluster[y, x] = k
            r = int(((x - cx)**2 + (y - cy)**2) ** 0.5)
            if r > max_r: max_r = r
            break

# Colour by attachment order with a sine-rainbow palette.
mask = cluster > 0
norm = (cluster[mask] - 1) / max(cluster.max() - 1, 1)
img = np.zeros((SIZE, SIZE, 3), dtype=np.uint8)
img[mask, 0] = (128 + 127*np.sin(norm*4 + 0)).astype(np.uint8)
img[mask, 1] = (128 + 127*np.sin(norm*4 + 2)).astype(np.uint8)
img[mask, 2] = (128 + 127*np.sin(norm*4 + 4)).astype(np.uint8)
Image.fromarray(img, mode='RGB').save('simple_dla.png')
```

<Admonition type="tip">
DLA is the **first algorithm in Module 04 where the shape is not predetermined by the rule**. Sierpinski's gasket is the same every time; the Mandelbrot set is mathematically unique. A DLA cluster's silhouette is statistically self-similar — the **fractal dimension** is reproducible, but the exact branches are not. Two runs with different seeds produce different clusters that look like siblings.
</Admonition>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — Random walkers with a sticking rule

The DLA algorithm is short: a `cluster` grid records which pixels are occupied; a sequence of random walkers approaches and sticks. Each walker:

1. **Launches** at a random point on a circle (radius = current cluster max + small margin) centred on the seed.
2. **Walks** by taking nearest-neighbour steps in `±x` or `±y` chosen uniformly at random.
3. **Tests** at every step: is any of the four 4-neighbour pixels already in the cluster? If yes, stick — set `cluster[y, x] = k` (with $k$ a step counter for colouring) and end the walker. If no, keep walking.
4. **Restarts** if the walker strays beyond a kill radius — the launch circle plus a margin. Without this safety valve, occasional walkers drift away from the cluster forever and the algorithm hangs.

The launch and kill radii are efficiency tweaks, not part of the physical model. The clean physical version says "launch from infinity"; in practice you launch from a circle close enough to the cluster that walkers hit it in reasonable time, and you kill walkers that stray off so they don't waste compute.

<Admonition type="dyk" title="Did you know · the universality of 1.71">
DLA clusters in 2D have fractal dimension $D \approx 1.713$ regardless of any microscopic detail [3]. Change the lattice geometry (square, hex, off-lattice), the walker step length, the bond type — none of it shifts the dimension by more than a couple of percent. The value seems to encode something fundamental about diffusion-driven growth. **No closed-form derivation of 1.71 exists**; it is known only from simulation [4]. It is one of the cleanest examples of a "universal constant" in non-equilibrium physics.
</Admonition>

### Concept 2 — The launch and kill circles

The cluster grows outward, so the launch radius must grow with it. The standard choice — and what the reference implementation uses — is to track the cluster's maximum extent from the seed and launch from `max_radius + margin`. Each new walker starts a few pixels outside the current "envelope" of the cluster.

The kill radius is similar: large enough that walkers approaching the cluster are likely to hit it, small enough that lost walkers die quickly. A factor of $\sim 2 \times$ launch radius is the conventional choice [4]. If the kill radius is too small, walkers struggle to ever reach the cluster (they keep restarting); if it is too large, walkers can wander deep into empty space before being killed.

Both choices are pure **bookkeeping**. They don't change the cluster's shape — they only change how fast you generate it.

### Concept 3 — Seed geometry decides the macro-shape

The micro-rule (random walk + stick on contact) is universal. The macro-shape of the cluster is decided by the **initial configuration** of stuck pixels:

- **A single seed.** Roughly radial dendrite, branching uniformly in all directions. The classic DLA "tumbleweed."
- **Two seeds, side by side.** Two clusters grow toward each other and outward; where they meet, neither extends because each blocks walkers approaching the other. The dividing line between their territories is roughly the perpendicular bisector — DLA's own Voronoi-like partitioning.
- **Three seeds in a triangle.** Three separate dendrites grow, each starving the others of incoming walkers — the "screening" effect that makes DLA dimension what it is.

The compulsion to see **shapes that look intelligent** — neurons, river deltas, vascular networks — comes from this universality. Whenever an aggregation process is dominated by diffusion of incoming material, you get DLA-like geometry. The macro-shape just records the local geometry of the boundary at the moment growth started.

<Admonition type="important">
DLA's "screening" effect explains why it is fractal. A walker approaching the cluster is far more likely to hit a **protruding tip** than to penetrate into a deep fjord — tips intercept walkers, fjords are shadowed. Tips therefore grow faster, which makes them protrude more, which makes them grow even faster. The positive feedback creates dendrites at every scale. Drop the screening (e.g. by letting particles "anneal" to the smoothest position) and DLA's dimension shifts toward 2.0, the filled disc [4].
</Admonition>

**Reflection questions**

- Roughly how does the runtime scale with the particle count? Linearly, quadratically, or super-linearly?
- Why do the cluster's branches taper as they get further from the centre? Tip: think about where each new walker is most likely to land.
- What would happen if you removed the `kill_r` check (let walkers wander forever)?

<Dropdown summary="Answers">

**Runtime scaling** — empirically super-linear, somewhere between $O(N^{1.5})$ and $O(N^2)$. Each new walker has to do more steps to find the cluster (the launch radius grows roughly as $N$ raised to the power $1/D$, with $D \approx 1.71$), and the per-walker random-walk path length grows as the launch radius squared. The product is around $N^{1.17}$ in the simplest analysis, but the constants matter for finite cluster sizes.

**Why branches taper** — screening. The cluster's tips intercept incoming walkers before they reach the deeper, older arms. Old arms therefore stop growing while tips elongate. The tapering you see is the cumulative record of which generations of branches were still "exposed" to the walker stream.

**No kill radius** — the algorithm would still work, but a small fraction of walkers would diffuse far away and never come back. Each such walker contributes nothing but wastes time. With unbounded canvases the runtime can become infinite in expectation, because a 2D random walk is **recurrent** (always returns to the origin eventually) but the expected return time is infinite.

</Dropdown>

</Exercise>

Reshape the mask into 4D blocks and use `.any()` along the within-box axes:

```python
H, W = mask.shape
# Crop to a multiple of box
```

`reshape` partitions the mask into a grid of $box \times box$ blocks; `any(axis=(1, 3))` collapses each block to a single boolean (true if any pixel is in the cluster); `sum()` counts the trues.

</Dropdown>

<Dropdown summary="Hint 2 — log-log fit">


`np.polyfit` returns the linear-regression coefficients. The dimension is the negative slope because we count occupied boxes against box **size** (not against the inverse size).

<CodeBlock lang="python" file="exercise3_solution.py">
```python
import numpy as np

def box_count(mask, box_sizes):
    counts = []
    H, W = mask.shape
    for box in box_sizes:
        Hb = (H // box) * box
        Wb = (W // box) * box
        blocks = mask[:Hb, :Wb].reshape(Hb // box, box, Wb // box, box)
        counts.append(int(blocks.any(axis=(1, 3)).sum()))
    return counts

def fractal_dimension(mask, box_sizes):
    counts = box_count(mask, box_sizes)
    log_eps = np.log(np.array(box_sizes, dtype=float))
    log_N   = np.log(np.array(counts,    dtype=float))
    slope, _ = np.polyfit(log_eps, log_N, 1)
    return -slope
```
</CodeBlock>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

Diffusion-limited aggregation is the fractal that emerges from random walkers sticking on contact. The micro-rule is trivial — launch on a circle, walk randomly, stick when touching the cluster, kill if you stray too far. The macro-shape is universal in dimension ($D \approx 1.71$ in 2D) but particular to the seed configuration. The launch and kill radii are bookkeeping for runtime, not part of the physical model. Screening — tips intercept walkers, fjords are shadowed — is what makes the dimension less than 2.0. The same algorithm describes electrodeposition, neuron growth, urban sprawl, and river deltas, which is why DLA appears in so many disjoint fields. With box-counting you can measure the dimension directly from the cluster and confirm it sits near the universal value — a clean experimental verification of a non-equilibrium constant that has no known closed form.

</Admonition>

**Common pitfalls to avoid**

- **Forgetting the kill circle.** A small fraction of walkers drift away forever, and the algorithm gets exponentially slower as the cluster grows.
- **Fixed launch radius.** The launch circle must grow with the cluster. Otherwise late walkers spawn inside the cluster's bounding circle and stick to it from the wrong direction.
- **8-neighbour vs 4-neighbour sticking.** Both work, but 8-neighbour produces marginally rounder branches and (slightly) higher dimension. The 4-neighbour version is closer to the canonical DLA literature value.
- **Reading too much into a single cluster.** Two clusters grown with different seeds will not look identical — only their **statistics** match. Always measure dimension by averaging across multiple runs.
