## Overview <a id="overview"></a>

The classical walk cycle is the foundational animation exercise: every character animator learns it first, every game character has one, every motion-graphics workshop teaches it [1]. The mechanical recipe — when distilled — is shockingly compact: **one sine wave** drives arm phase, the opposite phase drives leg phase, a 2× harmonic of that wave drives the body bob, and the whole composition loops cleanly because all phases share the same base period.

This lesson builds a procedural 8-frame stick-figure walk from scratch. No keyframes, no motion capture, no skeleton system — just trigonometry and per-frame polar limb placement. The result is sufficiently expressive for indie games, prototypes, and titles, and the same primitives extend to full skeletal rigging when you need realism (Module 12's GAN-based character animation builds on the same coordinate decomposition).

### Learning objectives

<ol class="obj-list">
  <li>Drive limb angles from a single shared phase variable using sine waves.</li>
  <li>Place arms and legs in **opposition** (180° phase offset) — the visual signature of natural walking.</li>
  <li>Add a 2× harmonic **body bob** that rises on each foot strike (twice per cycle).</li>
  <li>Render the cycle as both a sprite-sheet strip (for game use) and an animated GIF (for preview).</li>
</ol>

## Quick start — eight-frame walk <a id="quick-start"></a>

<CodeBlock lang="python" file="quick_start.py">
```python
import math
from PIL import Image, ImageDraw

CELL, N_FRAMES, LIMB = 140, 8, 35

def joint(x, y, length, angle_rad):
    return int(x + length * math.sin(angle_rad)), int(y + length * math.cos(angle_rad))

def render_pose(i, n=N_FRAMES):
    img = Image.new('RGBA', (CELL, CELL), (0, 0, 0, 0))
    draw = ImageDraw.Draw(img)
    phase = 2 * math.pi * i / n
    bob = int(2 * (1 - math.cos(2 * phase))) - 2
    cx = CELL // 2

    # Head + torso
    draw.ellipse([cx - 12, 18 + bob, cx + 12, 42 + bob], fill=(220, 230, 245))
    draw.line([(cx, 42 + bob), (cx, 80 + bob)], fill=(220, 230, 245), width=4)

    # Arms — phase
    arm_a = math.sin(phase) * 0.7
    rx, ry = joint(cx, 50 + bob, LIMB, math.pi + arm_a)
    draw.line([(cx, 50 + bob), (rx, ry)], fill=(220, 230, 245), width=4)
    lx, ly = joint(cx, 50 + bob, LIMB, math.pi - arm_a)
    draw.line([(cx, 50 + bob), (lx, ly)], fill=(220, 230, 245), width=4)

    # Legs — phase + pi (opposition)
    leg_a = math.sin(phase + math.pi) * 0.55
    rx, ry = joint(cx, 80 + bob, LIMB, math.pi + leg_a)
    draw.line([(cx, 80 + bob), (rx, ry)], fill=(110, 200, 255), width=4)
    lx, ly = joint(cx, 80 + bob, LIMB, math.pi - leg_a)
    draw.line([(cx, 80 + bob), (lx, ly)], fill=(110, 200, 255), width=4)
    return img
```
</CodeBlock>

<Admonition type="tip">
The arms and legs share **one phase variable**. Setting limb angle to `sin(phase)` for arms and `sin(phase + π)` for legs guarantees they're in perfect counterpoint without explicit synchronization. This is the cheapest possible implementation of "natural" locomotion.
</Admonition>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — One phase variable, multiple limbs

A walk cycle is **periodic** with period = one complete two-step cycle. Define a single phase variable `phase ∈ [0, 2π)` and let it advance linearly with frame index. Every limb angle is then a sine wave on this shared phase, with limb-specific amplitude and phase offset:

`arm_angle = sin(phase) * AMP_ARM`  
`leg_angle = sin(phase + π) * AMP_LEG`  
`body_bob = (1 - cos(2 * phase)) * AMP_BOB`

Three parameters per limb (amplitude, phase offset, frequency multiplier). For a full-body rig, this is dozens of parameters but only one phase clock. That single source of truth makes every limb's motion automatically synchronised.

### Concept 2 — Arms vs legs: 180° opposition

Real humans walk with the right arm forward when the left foot is forward. The right leg is forward when the left arm is forward. The two pairs are **anti-correlated**, which is what looks natural. In terms of phase, the opposition is exactly `π` radians:

<CodeBlock lang="python" file="opposition.py">
```python
arm_phase = sin(phase)              # at phase 0:  arm at neutral (0)
                                    # at phase π/2: arm fully forward
leg_phase = sin(phase + π)          # at phase 0:  leg at neutral (0)
                                    # at phase π/2: leg fully backward
```
</CodeBlock>

The reason is biomechanical [2]: arm swing counter-balances the angular momentum of the swinging leg, keeping the torso roughly stable. Take away the opposition — make both arms move the same way as both legs — and you get the comedic "Tin Man" walk that animators sometimes use deliberately. Doing it accidentally is the most common walk-cycle bug in early animations.

<Admonition type="dyk" title="Did you know · animators study Eadweard Muybridge">
Eadweard Muybridge's 1887 *Animal Locomotion* photographs sequenced human and animal movement at frame intervals for the first time — and they remain the reference for animators today [3]. The plates show the exact arm-leg opposition pattern (and 2× bob) that natural locomotion exhibits. Disney's "Nine Old Men" had Muybridge plates pinned to their desks; modern character animators still do.
</Admonition>

### Concept 3 — The 2× bob harmonic

A walking body **bobs up and down twice per cycle** — once for each foot strike. That's a **2× harmonic** of the base walk frequency. The formula:

`bob = (1 - cos(2 * phase)) / 2 * AMP_BOB`

At `phase = 0` and `phase = π` (both foot-strikes), bob is at its peak. At `phase = π/2` and `3π/2` (mid-step transitions), bob is at zero. Without this 2× harmonic the walk looks like a sliding glide — characters in early 3D games suffered from this all the time. Adding it costs one `cos` call and one constant amplitude.

The amplitude matters: too much bob looks like a jog or a hop; too little reads as no bob. Stay around 2–4% of body height for a relaxed walk, 5–8% for a confident stride, 10%+ for an exaggerated cartoon walk.

<Admonition type="important">
The 2× bob is the **first harmonic**, not a fundamental new wave. Once the phase clock exists, every body part's motion is some sine or cosine of `phase` or `2 * phase` (or `3 * phase` for hand-flicks, etc.). Procedural walk cycles are a constructive interference problem: pick the amplitudes and phase offsets of each harmonic to compose a natural-looking gait.
</Admonition>

**Reflection questions**

- Why is the body-bob amplitude set to 2 px (out of a 100 px-tall figure)?
- The legs and arms share a phase variable. What changes if the legs use `sin(2 * phase)` instead of `sin(phase + π)`?
- Where in the 8 frames does each foot make contact with the ground?

<Dropdown summary="Answers">

**Bob amplitude** — 2 px on a 100 px figure is 2% bob, which reads as relaxed natural walking. Doubling to 4% feels confident; 8% feels jaunty; 15% becomes a hop. The right amount is genre-dependent.

**Wrong-phase legs** — `sin(2 * phase)` makes legs cycle *twice as fast* as arms. The result looks like a comic two-stepping rhythm — legs whirring, arms strolling. Not naturalistic; sometimes used for cartoon characters with very fast feet.

**Foot contacts** — at `phase = 0` and `phase = π` (frames 0 and 4), the legs are at maximum extension — one forward, one backward. These are the foot-strike moments. The 2× bob peaks here because gravity catches the body's weight at these instants.

</Dropdown>

</Exercise>

<Exercise n={2} kicker="MODIFY" title="Sweep gait parameters">

Three variants.

**Goals**

1. **Sneak.** Reduce limb swing to 0.2 rad and bob to 1 px. The figure walks slowly, tip-toes.
2. **Jaunty walk.** Increase arm swing to 1.1 rad, leg swing to 0.7 rad, bob to 6 px. The figure marches.
3. **Reverse direction.** Negate the leg phase (use `sin(phase + π)` → `sin(phase)`) so legs are *in* phase with arms. The figure looks alien.

<Dropdown summary="Goal 1 — what to expect">

Subdued, cautious motion. Used for stealth animations in game characters. The slower the bob, the more deliberate the walk reads.

</Dropdown>

<Dropdown summary="Goal 2 — what to expect">

Marching, confident motion. Used for parades, hero entrances, and any "purposeful arrival" scenario.

</Dropdown>

<Dropdown summary="Goal 3 — what to expect">

The walk looks broken — arms and legs swing together instead of in opposition. Visually unsettling because human eyes are extremely sensitive to limb-opposition violations. Deliberately used for "uncanny" antagonist characters.

</Dropdown>

</Exercise>

<Dropdown summary="Hint 1 — head with nose">

```python
head_x = cx
head_y = 30 + bob
draw.ellipse([head_x - 12, head_y - 12, head_x + 12, head_y + 12],
             fill=(220, 230, 245))
# Nose: short line from centre toward facing direction
nose_x = head_x + int(8 * math.sin(head_angle))
nose_y = head_y + int(4 * math.cos(head_angle))
draw.line([(head_x, head_y), (nose_x, nose_y)],
          fill=(110, 200, 255), width=2)
```

The nose indicates head orientation; useful as a debugging cue for whether the rotation is rendering correctly.

</Dropdown>

<Dropdown summary="Hint 2 — head bob with body">

```python
# Make the head amplitude track the body bob — head bobs with body
head_y = 30 + bob - int(math.sin(phase * 0.5) * 2)
```

Compound motion: body bob + slow head sway. Reads as natural exploration.

</Dropdown>

<Dropdown summary="Complete solution">

The walk now feels more alive because the head looks around as the figure moves. Same principle works for tail wag (use `sin(2 * phase)` like a dog's) or for an antenna on a robot.

</Dropdown>

#### Make it your own

- **Speed modulation.** Tie phase advance to a `speed` parameter. Slow speed = sneak; fast speed = run. The same walk cycle scales smoothly.
- **Running.** Increase leg swing to 1.0+ rad and bob to 8 px. Add an "air time" pose where both feet are off the ground simultaneously.
- **Two characters.** Render two figures with different phases offset by π/4 — a duet of walks. Useful for parade or marching sequences.

</Exercise>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

A walk cycle is built from one phase clock and a sequence of sines: arms at `sin(phase)`, legs at `sin(phase + π)` (opposition), body bob at `(1 - cos(2 * phase)) / 2` (2× harmonic). Per-limb amplitude controls the gait — small swings for sneaks, large for marches. The composition automatically loops because every term shares the base period $2\pi$. Same primitive scales to skeletal rigging in 3D and to procedural character animation in 2D games. The pattern recurs throughout Module 08 — every cyclic animation in the rest of the module (breathing, infinite blossoms, music visualization) is a variation on "one clock, many sines."

</Admonition>

**Common pitfalls to avoid**

- **Same phase for arms and legs.** Animation reads as broken. Always offset legs by π.
- **No body bob.** The walk slides — looks like the character is rollerblading. The 2× harmonic is what reads as footfall.
- **Phase clock not loop-aligned.** If the cycle ends mid-step, the GIF loop has a visible hitch. Make sure `FRAMES * step_per_frame = 2π` for a clean loop.
- **Forgetting to scale phase to the loop length.** Increasing `N_FRAMES` requires reducing the per-frame phase advance proportionally.
