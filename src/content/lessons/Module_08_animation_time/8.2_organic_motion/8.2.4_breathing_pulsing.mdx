## Overview <a id="overview"></a>

Some of the most effective animations are the ones the viewer *doesn't consciously notice*. A static portrait that "breathes" — chest scales vertically by 2.5% on a slow sine wave — reads as a living human even though the modulation is mathematically tiny. A logo that "pulses" — uniform scale by 4% on a 1-second cycle — feels active without being distracting. A video that "glitches" — RGB channels rolled by a few pixels on opposite sines — reads as VHS-era footage with no real damage applied.

This lesson covers three of the smallest possible sine-driven modulations that transform stills into ambient-life animations: **breathing** (vertical scale), **pulsing** (uniform scale), and **channel-roll glitch** (per-channel translation). Every one of them is a 3-line function. Together they cover the vast majority of "living wallpaper" effects on every social-media platform and the loading-state subtleties of every modern app.

### Learning objectives

<ol class="obj-list">
  <li>Apply a sinusoidal vertical scale to simulate breathing — the chest expands and contracts on a slow cycle.</li>
  <li>Apply a sinusoidal uniform scale to simulate pulsing — the whole figure rhythmically grows and shrinks.</li>
  <li>Apply a sinusoidal channel roll (R, G, B shifted by different small amounts) to simulate chromatic-aberration glitch.</li>
  <li>Compose multiple modulations onto the same subject to create cumulative ambient effects.</li>
</ol>

## Quick start — three modulations in 90 frames <a id="quick-start"></a>

<CodeBlock lang="python" file="quick_start.py">
```python
import math, numpy as np
from PIL import Image

def breathing(base, t):
    scale_y = 1.0 + 0.025 * math.sin(2 * math.pi * t)
    H, W = base.size[1], base.size[0]
    scaled = base.resize((W, int(H * scale_y)), resample=Image.BILINEAR)
    out = Image.new('RGB', (W, H), (24, 28, 38))
    out.paste(scaled, (0, H - int(H * scale_y)))    # anchor at bottom
    return out

def pulsing(base, t):
    scale = 1.0 + 0.04 * math.sin(2 * math.pi * t)
    H, W = base.size[1], base.size[0]
    nh, nw = int(H * scale), int(W * scale)
    scaled = base.resize((nw, nh), resample=Image.BILINEAR)
    out = Image.new('RGB', (W, H), (24, 28, 38))
    out.paste(scaled, ((W - nw) // 2, (H - nh) // 2))
    return out

def glitch(base, t):
    arr = np.array(base)
    arr[:, :, 2] = np.roll(arr[:, :, 2], int(8 * math.sin(2 * math.pi * t)), axis=1)
    arr[:, :, 1] = np.roll(arr[:, :, 1], int(4 * math.sin(2 * math.pi * t + math.pi/2)), axis=0)
    return Image.fromarray(arr)
```
</CodeBlock>

<Admonition type="tip">
All three effects use the **same** sinusoid `sin(2 * π * t)` and the **same** loop period of $N$ frames. What differs is the operator applied — vertical resize, uniform resize, channel roll. The architecture is one sine wave driving N different transformations of the same base image.
</Admonition>

## Core concepts <a id="core-concepts"></a>

### Concept 1 — Breathing: anchored vertical scale

Real breathing is **chest expansion** — the body's lower half stays roughly in place while the upper half rises and falls. To simulate this with a 2D image transformation:

1. Scale the image vertically by `1 + amplitude * sin(2π * t)` (typically 2-4% amplitude).
2. **Paste the result anchored at the bottom** of the canvas, not centred. This makes the chest "rise" from a fixed waist line.

If you accidentally centre the scaled image, the figure floats up and down instead of breathing. Anchoring is what distinguishes the two effects.

<CodeBlock lang="python" file="anchor.py">
```python
new_h = int(H * scale_y)
out.paste(scaled, (0, H - new_h))     # bottom-aligned
```
</CodeBlock>

### Concept 2 — Pulsing: uniform scale around the centre

Pulsing is simpler — scale both axes by the same factor, then centre the result:

`scale(t) = 1 + amplitude * sin(2π * t)`

A 4% amplitude is the sweet spot. Smaller and the pulse vanishes; larger and the figure feels nervous. Use uniform scaling (not just vertical) so the geometry stays proportionate, and centre the result so the pulse feels balanced.

The visual cue is "this thing is alive but stationary" — useful for logo splash screens, button hover effects, app icon animations, and meditation app focus markers.

<Admonition type="dyk" title="Did you know · the iOS app icons that pulse">
Apple's HIG (Human Interface Guidelines) recommends a subtle pulse for *active* interactive elements like loading buttons. The exact specification (in iOS 17 Apple uses a 4% scale modulated by a 1.5-second sine wave) matches the breathing-rate range of 12–16 breaths per minute for an adult at rest [1]. Designers intuitively pick "breathing" timings because viewers unconsciously synchronize their own breath to onscreen rhythms — the so-called *physiological resonance* effect [2].
</Admonition>

### Concept 3 — Channel-roll glitch: chromatic aberration

The channel-roll effect from 8.1.1 (`np.roll` per channel) becomes a glitch animation when the roll amount is time-varying:

<CodeBlock lang="python" file="glitch.py">
```python
arr[:, :, 2] = np.roll(arr[:, :, 2], int(8 * math.sin(2 * π * t)), axis=1)
arr[:, :, 1] = np.roll(arr[:, :, 1], int(4 * math.sin(2 * π * t + π/2)), axis=0)
```
</CodeBlock>

The phase offsets (`π/2`) ensure the channels drift in different directions at different moments, producing the characteristic colour-separated look of bad VHS playback. Small amplitudes (4-8 pixels) read as a subtle glitch; larger amplitudes look like the video is actively malfunctioning. Use sparingly — it tires the eye quickly.

<Admonition type="important">
The three modulations are **compositional**. Apply breathing, then pulsing, then glitch on the same subject — you get a portrait that breathes, pulses, and glitches simultaneously. As long as each modulation uses a different frequency, they remain visually distinct rather than blending into one effect.
</Admonition>

**Reflection questions**

- The breathing animation anchors at the bottom. What does the figure look like if you anchor at the *top* instead?
- The pulsing GIF uses a centred paste. What happens if you offset the paste by 10 pixels in one direction?
- The glitch uses phase `π/2` between blue and green. What does the glitch look like with phase 0?

<Dropdown summary="Answers">

**Top-anchored breathing** — the head stays fixed while the chest descends. Visually reads as the figure being squished downward, not breathing — wrong direction. Real bodies expand upward as lungs inflate.

**Off-centre pulse** — the figure pulses *toward* one direction. Useful for "boop" effects on bumper-pinball-style indicators, but wrong for general-purpose "active" animations.

**Phase 0 glitch** — blue and green both shift the same way at the same time. Reduces the chromatic aberration to a uniform horizontal shake, which doesn't read as glitch — just as motion. The phase offset is what separates the channels.

</Dropdown>

</Exercise>

<Exercise n={2} kicker="MODIFY" title="Sweep amplitudes and frequencies">

Three variants of the breathing effect.

**Goals**

1. **Deep breath.** Increase amplitude to 0.08 (8%). The figure looks like it is taking a deliberate breath rather than ambient resting.
2. **Holding breath.** Use `breath(t) = max(0, sin(2π * t))` instead of `sin` — only positive lobes. The figure inhales and holds, never exhaling.
3. **Two-frequency mix.** Add a faster jitter on top of the breath: `scale = 1 + 0.025 * sin(2π * t) + 0.005 * sin(2π * t * 8)`. The figure breathes and trembles slightly.

<Dropdown summary="Goal 1 — what to expect">

Deliberate, visible breathing. Used for meditation-app figures showing exemplar breath rhythms; clearly readable as "this is breathing" rather than "this is alive."

</Dropdown>

<Dropdown summary="Goal 2 — what to expect">

The figure inhales over half the cycle, then *snaps* back to baseline at the bottom of the breath instead of smoothly exhaling. The result feels tense — useful for anxiety indicators or panicked characters.

</Dropdown>

<Dropdown summary="Goal 3 — what to expect">

Subtle trembling on top of the breathing — reads as cold, sick, or stressed. The composition of two sine waves at different frequencies (called **beat frequencies**) is the basis of every "complex modulation" effect in audio and animation.

</Dropdown>

</Exercise>

<Dropdown summary="Hint 1 — two-pulse heartbeat">

```python
def heartbeat(t):
    if t < 0.08:
        return math.sin(t / 0.08 * math.pi)              # first pulse
    if t < 0.16:
        return 0
    if t < 0.22:
        return math.sin((t - 0.16) / 0.06 * math.pi) * 0.7  # second smaller pulse
    return 0
```

Two short sinusoidal pumps with a brief pause in between — the cardiac systole/diastole pattern.

</Dropdown>

<Dropdown summary="Hint 2 — pulsing arc">

```python
angle = 2 * math.pi * t

arc_end = math.degrees(angle + math.pi / 2)
draw.arc([cx - r, cy - r, cx + r, cy + r],
         arc_start, arc_end, fill=(110, 200, 255), width=6)
```

Combine rotation (angle proportional to time) with size pulsing (radius modulated by heartbeat). The result reads as "alive and processing."

#### Make it your own

- **Camera shake.** Apply small per-frame x/y offsets (`int(2 * sin(2π * t * 10))`) for a subtle handheld-camera feel. Combines well with breathing.
- **Eye blink.** Render eyes as ellipses with vertical scale `1 - blink(t)` — blink is a 0.1-second cosine pulse triggered every 4 seconds.
- **Mouse-driven pulse.** Pulse amplitude proportional to mouse distance from a target — the UI gets more excited as the cursor approaches.

</Exercise>

## Summary <a id="summary"></a>

<Admonition title="Key takeaways">

Three tiny sinusoidal modulations turn stills into animated life: **breathing** (vertical scale, bottom-anchored, 2-4% amplitude), **pulsing** (uniform scale, centred, 4% amplitude), and **channel-roll glitch** (per-channel translation with phase offset). Each is a 3-line function. Each uses `1 + amplitude * sin(2π * t)` as the modulation formula. Each costs almost nothing computationally. The architecture pattern — "one sine wave drives N different operators" — is the most expressive minimal-effort animation idiom in the field, used in every iOS app, every social media platform, and every meditation app for ambient-life cues.

</Admonition>

**Common pitfalls to avoid**

- **Centred-instead-of-bottom-anchored breathing.** Looks like floating, not breathing.
- **Too-large amplitudes.** A 10% breathing scale reads as a body builder flexing; 2-4% reads as ambient life. Less is more.
- **Same phase across glitch channels.** No colour separation — looks like uniform shake instead of chromatic aberration. Use π/2 offset between channels.
- **No looping consideration.** If your sine doesn't complete an integer number of cycles within `N_FRAMES`, the GIF loop will hitch. Always make `N_FRAMES * dt = 2π * (cycles)` exactly.
