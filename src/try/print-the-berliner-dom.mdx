<TryStep n={1} kind="predict" title="Ask a yes/no question" minutes={3} concept="brightness">

`light < THRESHOLD` asks one yes/no question: is this pixel darker than the threshold? The answer is `True` or `False`.

<Diagram folder="/try-media/fig" name="four-pixels" ext="webp" phoneHeight={1250} alt="The Dom photo with four pixels circled: stone in shadow, sky, green dome, stone. Each has three numbers, red, green and blue, and one brightness: 30, 200, 120 and 90." caption="The four numbers in the code are these four pixels." />

<Task slot="task">Before you run: which numbers will print `True`? Run. Then change `THRESHOLD` on line 1 so exactly three squares get ink.</Task>

<Theory slot="theory" title="Watch out" line="line 4" list="watch out: < is not ≤">

`120 < 120` is `False`: a pixel exactly at the threshold stays paper.

</Theory>

<Hint>`30 < 100` is `True`; `200 < 100` is `False`. Do the other two the same way.</Hint>
<Hint>The three darkest numbers are 30, 90 and 120. The threshold must be above 120 and no more than 200.</Hint>
<Hint kind="solution">`THRESHOLD = 150`</Hint>
<Hint kind="explain">A threshold is a mark on a ruler from 0 to 255. Every number left of the mark is `True` and gets ink; every number right of it stays paper.</Hint>

<TryStep n={2} kind="write" title="Ink the dark pixels" minutes={2} concept="threshold">

<Task slot="task">Replace `___` so that dark pixels (below `THRESHOLD`) return the ink.</Task>

<Hint>The name on line 6 is `light`; the number to compare it with is on line 2.</Hint>
<Hint kind="solution">`if light < THRESHOLD:`</Hint>
<Hint kind="explain">The rule works like a door check: each pixel shows its brightness, the rule asks one question and sends the pixel to the ink pile or the paper pile.</Hint>

<TryStep n={3} kind="fix" title="The blue that never shows" minutes={3} concept="bands">

Three inks need two questions: below 90 blue, below 150 pink, the rest paper. Python reads the `if`s from the top.

<Task slot="task">This rule should give three tones: blue ink, pink, paper. No blue shows. Change the order of the two `if`s so the blue appears.</Task>

<Theory slot="after" title="Why it worked" line="lines 7 and 9" list="why it worked: narrow first">

<Diagram folder="/try-media/fig" name="if-order" ext="webp" phoneHeight={1230} alt="Two rulers. With the below-90 question first: blue, pink and paper bands, and a pixel at 10 lands in blue. With the below-150 question first: only pink and paper; the pixel at 10 stops in pink." caption="The same two `if`s in both orders. A pixel at 10 stops at the first `True`." />

In a chain of `if`s the first `True` wins, so the narrow question (below 90) goes before the wide one (below 150).

</Theory>

<Hint>Brightness 10 is below 150, so the first `if` already answers for it. Which `if` should come first?</Hint>
<Hint>Check `light < 90` first, then `light < 150`. Keep the numbers.</Hint>
<Hint kind="solution">Move `if light < 90:` and its `return INK` above `if light < 150:`.</Hint>
<Hint kind="explain">Picture two doors in a row. A pixel walks through the first door that lets it in. If the wide door (below 150) comes first, every dark pixel takes it and nobody reaches the narrow one.</Hint>

</TryStep>

<TryWrap minutes={2} recall={["brightness", "threshold", "bands"]}>

- A pixel is three numbers; their average is its brightness, 0 to 255.
- `<` asks a yes/no question; a function turns the answer into an ink.
- In a chain of `if`s the first `True` wins, so the narrow question comes first.
